# 大工程性能验收（demo 工程）

> 目的：在 IDEA 版插件自带的 demo 工程（真实规模、21 个模块）上验证 OpenIDEA 端口**没有性能问题**。
> 结论：核心路径与索引成本都远低于预算；索引是一次性后台工作，跑完后 CPU 归零、内存不增长。
> 环境：OpenIDEA 0.1.51（`D:\RuanJian\OpenIDEA`）、本仓 `master`（`c457683` 及之前的 `sqlv_index_stats`）、
> Windows 10.0.26200 x64。工程：`F:\code\Java\Gitee\SongRenShuo\mybatis-plus-sql-visualizer-demo`。

## 1 工程规模（实测）

| 项 | 数值 |
| --- | --- |
| 目录体积 | 363 MB |
| Maven 模块 | 21（`cust-big-demo` 单独 182 MB） |
| 磁盘 `.java` | 17142（含 `target/` 副本） |
| 磁盘 mapper XML | 4098（含 `target/` 副本） |
| **IDE 交给插件的文档** | **12437 个 / 50.0 MiB**（`target/` 等被宿主排除，所以比磁盘少） |

## 2 插件自身索引（`sqlv_index_stats` 实测）

| 预算 | Java 文件 / 方法 | XML 文件 / 语句 | 跳过 | 总耗时 | 平均 / 最慢单文档 |
| --- | --- | --- | --- | --- | --- |
| 旧：4096 / 16 MiB，XML 4096 | 4096 / 52475 | 2346 / 13055 | Java 5900，XML 95 | 1451.5 ms | 0.12 ms / 8.7 ms |
| 新：20000 / 64 MiB，XML 12000 | **9996 / 166529** | 2346 / 13055 | **Java 0**，XML 95 | **3613.2 ms** | 0.29 ms / 14.8 ms |

读数解释：

- 文档数与字节数两轮相同（12437 / 50.0 MiB）——宿主投递的是同一批文档，预算只决定「存不存」。
- 旧预算把 5900 个 Java 文件挡在外面（这些行的「跳转 Java」没有目标）；放宽后 **Java 丢弃为 0**，代价是总耗时 1.45 s → 3.6 s，
  仍是**一次性后台**成本（平均 0.29 ms/文档）。
- XML 的 95 个跳过是解析失败/非 mapper 形态（不是预算），XML 侧文件数 2346 远低于上限。
- 索引跑完后：进程 RSS **509 MB**（旧预算下 516 MB，两者相当），CPU 在 55 秒采样窗口内只涨 0.1 s（**空闲**）。

## 3 核心解析路径（MCP 端到端，等价命令侧）

| 场景 | 输入规模 | 读数（3 次） |
| --- | --- | --- |
| `sqlv_render_sql`（大 mapper） | 16 KB，11 条语句 / 91 个动态标签 | min 4 ms / **median 24 ms** / max 29 ms |
| `sqlv_check_sql`（宽表 SQL） | 200 列 | 4 ms |
| `sqlv_render_logs` | 7200 行 / 935 KB | 210 / 232 / 255 ms（**median 231 ms**，含 HTTP 与 1.7 MB 回包） |
| `sqlv_index_stats` | 无入参 | 3 ms |

平台限制：MCP 入参 **1 MiB** 上限（1.3 MB 日志被宿主拒绝，`MCP arguments exceed 1 MiB`），大日志走面板/文件路径。

## 4 面板推送

5k 行（`logs.pageSize` 上限调到 5000、全部序列化）：**181.7 / 195.0 ms**（debug 构建，`views::log_panel` 单测实测），
默认 50 行时成本远低于此。判定：< 200 ms 预算，达标（debug 数；release wasm 更快）。

## 5 判定

| 指标 | 预算 | 实测 | 结论 |
| --- | --- | --- | --- |
| 命令侧解析（16 KB mapper / 200 列 SQL / 7.2k 行日志） | 5 s | 24 ms / 4 ms / 231 ms | 通过 |
| 面板 5k 行推送 | < 200 ms | 182–195 ms（debug） | 通过 |
| 插件索引（全工程一次） | 后台完成、不阻塞编辑 | 3.6 s / 12437 文档 / 50 MiB；之后 CPU 归零 | 通过 |
| 常驻内存增量 | 无异常增长 | RSS 509 MB（含 IDE+jdtls），与旧预算持平 | 通过 |
| provider 延迟 | 软 50 ms / 硬 500 ms | 未单独计时（见下） | 待补 |

**未完成项**：provider（诊断/inlay/导航）的单次延迟没有单独计时。原因：设置页无法自动化打开这几个开关（缺陷 D5），
真机无法在开启状态下取到稳定读数。代码路径已按「单文档、内存查询」写（诊断只读当前文档文本 + 列清单），
下一轮若拿到设置通道，用「同一 mapper 文件反复触发」的方式补测。

## 6 复现方法

1. `openidea-plugin build && openidea-plugin link .`，重启 OpenIDEA。
2. 打开 demo 工程；等状态栏 `Searching…` 结束、CPU 采样归零（约 3–4 分钟，宿主扫描为主）。
3. 读索引成本：MCP 调 `sqlv_index_stats`（HTTP `?project=<工程路径>`），或 Find Action 跑 `index-stats`。
4. 核心路径：MCP 调 `sqlv_render_sql`（`CustAddressMapper.xml` + `selectByExample`）、`sqlv_render_logs`（大日志文本）、`sqlv_check_sql`。
5. 资源：`Get-Process openidea` 采 `WorkingSet64` 与 `CPU`，间隔 5 s 连续 12 次判是否持续增长。
