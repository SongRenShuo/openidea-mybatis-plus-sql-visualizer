# 面板整体失效的根因是模板字符串被注释里的反引号闭合

- 日期：2026-11-27
- 现象：SQL 日志工具窗打开后只有一个下划线，五个页签没有文字，工具栏图标在但点了没反应，正文空白。
- 影响面：整个插件 UI 全不可用，但 `cargo fmt` / `clippy` / `test` 全绿，包也打得出、装得上。

## 根因

`web/preview.js` 里 `const TEMPLATE = \`…\`` 横跨第 28–159 行。第 104 行的 HTML 注释写成了：

```js
<!-- Qualify columns (lane L44): rendering `table.column` needs the
```

反引号在模板字符串内部就是字面量的结束符。第一个反引号（在 `table` 前）把 `TEMPLATE` 提前闭合，剩下的 `<span>…</span>` 之类变成了裸表达式，第二个反引号又开了一个新字面量——最终整份模块抛 `SyntaxError: Unexpected identifier 'table'`。

`web/log-panel.html` 用 `<script type="module">` + `import { mountPreview } from './preview.js'` 挂载预览。ES 模块的解析失败会让**整段脚本**不执行，不是只坏一个函数。于是：

- 页签文字没被填 → 只剩空按钮
- `addEventListener` 全部没注册 → 工具栏按下无反应
- 面板正文没被渲染 → 空白

一次解析失败，视觉上就是「所有功能都不可用」，看上去像宿主管道断了，其实一行 JS 都没跑起来。

## 为什么没有门禁拦住

`web/` 下的文件 Rust 侧一律不读：它们只在 `openidea-plugin build` 时按 `web_files()` 打进包里，编译、单测、`check` 全都不解析 JS。所以这道门在本地和 CI 都是空的——绿灯只证明 Rust 编得过。

## 修法

1. 去掉注释里的反引号（写 `table.column`，不写 `` `table.column` ``）。
2. 加 `scripts/check-web-syntax.mjs`：用 `node --check` 权威解析 `web/*.js`，并把每个 HTML 的 `<script>` 内容抽出来落临时 `.mjs` 再解析（行内脚本同样是面板主逻辑）。跳过 `<script src>` 与 `type="application/json"` 这类非 JS 类型。
3. 加 `scripts/check-web-syntax.test.sh`，五档夹具自测：干净必须绿、模板串内反引号必须红、行内脚本语法错必须红、非 JS type 要跳过、缺 `web/` 目录必须报错（防止路径写错时「0 个文件全通过」的空绿）。
4. 接进 `build.yml` 的 `static` job，排在 `cargo fmt` 之前——它比 Rust 那几道都快。

## 反向验证（必做）

把 bug 原样放回 `web/preview.js`：

```
error: web/preview.js:         <!-- Qualify columns (lane L44): rendering `table.column` needs the
                                                    ^^^^^
SyntaxError: Unexpected identifier 'table'
1 of 3 web script(s) failed to parse.
exit=1
```

恢复修复版后 `ok: 3 web script(s) parse`，`exit=0`。同一处 bug 精确报红，不是靠别的文件顺带变红。

## 可复用的判断

- **「所有功能同时失效」先怀疑整段脚本没执行，别先怀疑宿主。** 页签文字、按钮回调、正文渲染全由同一段脚本初始化，一起消失就是解析/加载失败的特征；只有单个功能坏才是逻辑 bug。
- **模板字符串里写文档注释有风险。** 反引号（以及 `${`）在模板字面量内都有语义。在 HTML 模板里加注释时，注释内容不要用反引号括标识符。
- **打包进产物的静态资源必须有独立的语法门禁。** 编译器不读的文件等于没被校验过；「能打包」和「能运行」之间隔着一个解析器。
