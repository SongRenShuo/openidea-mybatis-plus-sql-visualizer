# 引擎 sidecar：stdio、编码、驱动与重钉

> 归属：跨任务复用（JVM sidecar 与 jar 打包）。

## 1 只有 jar 没有 stdio 入口 = sidecar 永远握手失败

引擎 jar 起初只有 API 类，没有 `Main-Class`。`sidecar::start()` 只能 `HandshakeFailed` 降级。
配方：在引擎仓加一个最小的 `StdioMain`（逐行读 JSON、调 `EngineApi`、逐行写 JSON、坏行返回
结构化错误不退出），并在 jar manifest 写 `Main-Class`；`java -jar <jar> --stdio` 即通。

真机读数：spawn→ping 约 204 ms；`id` 原样回显；坏 JSON 返回 `kind:"invalid"` 进程存活。

## 2 中文 Windows 的 stdout 编码会污染协议

JVM 默认 `stdout.encoding=GBK`，中文错误信息按 GBK 写出，UTF-8 解析端读到乱码/断帧。

配方：`StdioMain` 启动时显式把协议流设为 UTF-8（`new PrintStream(..., "UTF-8")` 或
`-Dstdout.encoding=UTF-8`），stderr 只放日志。

## 3 打包去重会丢 `META-INF/services`

fat jar 合并依赖时，若对 `META-INF/services/java.sql.Driver` 做「先到先得」去重，
PostgreSQL 或 SQL Server 的 Driver 声明会被丢掉，`DriverManager` 找不到驱动。

配方：对 `META-INF/services/*` 做**内容合并**（保留每行、去重行），不要整文件取一个。

## 4 重建 jar 后必须重钉 sha256

`engine/ENGINE_VERSION.sha256` 与 sidecar 的钉值测试要同时更新；顺序：
`./gradlew :engine-jar:jar` → `sha256sum` → 改 `.sha256` 与 `src/sidecar/mod.rs` 钉值 →
`bash scripts/verify-engine.sh <jar>`（exit 0）→ `cargo test sidecar`。

## 5 CI 没有 jar，校验脚本要支持 `--pin-only`

仓库只钉版本与 sha256，jar 不入库。`verify-engine.sh` 完整模式在 CI 必然 `exit 3`。
配方：加 `--pin-only`（只校验 semver 与 64 位 hex），CI 用它；开发者有 jar 时跑完整模式。

## 6 许可白名单决定能执行哪些库

- PostgreSQL JDBC（BSD-2）、mssql-jdbc（MIT）可随 jar 分发。
- MySQL Connector/J 是 GPLv2+FOSS、H2 是 MPL/EPL，均禁入；因此 EXPLAIN 只对 PG/SQL Server 真执行。
- 驱动全文写进 `NOTICE` 与主仓 `THIRD-PARTY-NOTICES.md`。

## 7 安装态读不到包内 jar

安装只复制 manifest 引用文件 + wasm，没有安装目录路径，插件只有 `fs.plugin_dir()`。
分发改为「首次 `net:` 下载到 `plugin_dir` + sha256 校验」；`engine.downloadUrl` 默认为空即不联网、
降级纯文本。开发态（link）可直接用仓库 `engine/mpsv-engine-<ver>.jar`。
