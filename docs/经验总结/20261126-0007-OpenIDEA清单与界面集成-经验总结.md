# OpenIDEA 清单与界面集成：命令参数、菜单与面板刷新

> 归属：跨任务复用（清单声明、命令传参、视图渲染）。

## 1 Find Action 不传命令参数

`run-command` 的 `argument` 只在三种入口有值：`executeAction("plugin.<id>.<cmd>", "arg")`、
通知按钮（`NotificationAction` 带 `.argument`）、状态栏/视图条目菜单。**Search Everywhere /
快捷键调用时 `arg = None`**。

后果：只靠 Find Action 无法验收 `render-xml`、`check-sql`、`generate-crud` 这类需要路径/JSON
的命令。

可用配方（不写业务代码）：在 `plugin.toml` 加一条项目视图菜单，选中文件的首个路径会成为参数：

```toml
[[contributes.menus]]
menu = "projectView.context"
command = "capture-open-log"
```

右击文件 → 菜单出现命令 → 执行时 `arg` 即该文件路径（`ctx.selected_paths()` 的第一个）。
`viewItem.context` 菜单在表格行上则把行号（十进制字符串）作为参数。

## 2 视图已打开时 `reveal_view` 不会重渲染

`src/views` 的面板用模块级缓存 + `dirty` 标记；命令里 `set_log_text()` 只置脏。
当面板已经可见时，`host::reveal_view(VIEW_ID)` 只切焦点，不触发 `Views::render`，
界面停在旧数据（空态）。

配方：数据变更命令在 reveal 之后补一次 `host::refresh_view(VIEW_ID)`；单测用
`MockHost::refreshed_views()` 断言该视图在列。

## 3 清单计数的复读方式

`openidea-plugin check .` 会打印 `contributes N × commands / views / providers / mcpTools /
documentIndexers / markerIcons / fileIcons / settings / menus / javaAgents` 与能力分级，
是判断「注册有没有真的生效」的最快读数；`build` 只保证组件能编译，不校验清单语义。

## 4 设置页与 schema

`[contributes.settings] schema = "<包内 json>"` 的字段类型只接受
`boolean / string / number / integer`，没有 `number` 与代码侧 `Kind` 的一一映射时要统一
（本仓最终把 `logs.pageSize` 定为 `integer`）。设置页标题走插件 catalog（`locales/*.json`），
代码里的 `messageKey` 走 `src/i18n.rs`，两者不要混。

## 5 视图的两种实现

- 代码渲染：`Body::Html` / `Body::Table` 等，`Views::render` 返回结构，`Viewport` 分页。
- 包内页面：`web = "web/xxx.html"`，页面通过 `openidea.postMessage/onMessage` 通信，
  CSP 内无外链、无网络。

同一个视图不要既声明 `web` 又靠代码渲染正文。
