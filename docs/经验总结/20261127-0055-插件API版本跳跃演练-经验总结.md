# 插件 API 版本跳跃演练经验总结

> 场景：仓库钉在 `engines.openidea = "^1.15"`（SDK `v0.1.51`），上游 `main` 已经是 API 1.18。
> 在**临时副本**里把 SDK 指向 `branch = "main"`，看本仓能不能编过、编不过会撞什么。
> 时间：2026-11-27。SDK 对比：`v0.1.51`＝`30e72ffa5`（API 1.15），`main`＝`64097d3c2`（API 1.18）。

## 结论先说

本仓全量在 1.18 SDK 下**不需要改一行源码就能编译**。1.15 → 1.18 是纯增量：没有删任何本仓用到的
公开项，`reveal_view`、`ViewEvent`、`views`、`host` 的签名都没变。切换时要动的是版本号六处
（脚本一次改完，见 §5）、以及 `Cargo.lock` 重解析。

## 1 演练做法

```sh
DRILL=$(mktemp -d /tmp/l47-drill.XXXXXX)
# 只复制工作树，不带 .git / target / dist
tar -cf - --exclude=.git --exclude=target --exclude=dist . | (cd "$DRILL" && tar -xf -)
# 依赖从 tag 改成 branch
#   Cargo.toml: openidea-plugin = { git = "...", tag = "v0.1.51" }
#            -> openidea-plugin = { git = "...", branch = "main" }
export CARGO_TARGET_DIR=/tmp/l47-target      # 不污染本仓，也不撞共享 target 锁
cargo check --target wasm32-wasip2
```

`CARGO_TARGET_DIR` 指到临时目录这一点是必要的：本机同时有别的车道在跑 `cargo test`，
共享 `target/` 会撞文件锁。本次没撞上，但临时 target 让三次演练（wasm / host / 基线对照）
可以互不等待。

## 2 读数

| 演练 | 命令 | 结果 | 耗时 |
| --- | --- | --- | --- |
| 1.18 本仓 lib | `cargo check --target wasm32-wasip2` | **通过**，0 error 0 warning | 2m08s |
| 1.18 本仓全 targets | `cargo check --all-targets --target wasm32-wasip2` | **失败**，47 error（见 §3） | — |
| 1.18 本仓全 targets（宿主三元组） | `cargo check --all-targets` | **通过**，0 error 0 warning | 46.84s |
| 对照：v0.1.51 全 targets（wasm） | `cargo check --all-targets --target wasm32-wasip2` | **失败**，同样 47 error | — |

第一条是任务要求的那一条，通过。缓存冷启（拉 SDK + 编 `wit-bindgen` 一族）2m08s，
比主控给的最小 crate 参考值 3m10s 短，因为共享了 `~/.cargo` 的 git 检出与 registry 缓存。

## 3 `--all-targets --target wasm32-wasip2` 的 47 个错误：与升级无关

```
error[E0433]: cannot find `mock` in `openidea_plugin`   × 6
error[E0432]: unresolved import `openidea_plugin::mock` × 37
note: found an item that was configured out
   --> sdk/rust/openidea-plugin/src/lib.rs:52:9
 51 | #[cfg(not(target_arch = "wasm32"))]
 52 | pub mod mock;
```

全部同一个根因：SDK 的 `mock` 模块（`MockHost`，测试桩）用
`#[cfg(not(target_arch = "wasm32"))]` 门住了，只在宿主三元组编译。本仓的测试大量
`use openidea_plugin::mock::MockHost`，这些测试**本来就不能跑在 wasm target 上**。

判据是**对照实验**，不是推理：把同一份工作树换回 `tag = "v0.1.51"`，同样跑
`--all-targets --target wasm32-wasip2`，错误数一模一样（47 个，E0432×37 + E0433×6）。
所以这 47 条是仓库与 target 组合的既有性质，1.18 没有引入任何新错误。

对应到 CI：`cargo test` 不带 `--target`（`.github/workflows/build.yml` 的 `test` job 是裸
`cargo test`），跑的是宿主三元组，所以 CI 一直没被这个问题绊住；`clippy --all-targets`
同理也是宿主。**演练时别拿 `--target wasm32-wasip2 --all-targets` 的红色当升级风险**，
那不是升级造成的。

## 4 1.15 → 1.18 到底加了什么（guest 侧）

看 `sdk/rust/openidea-plugin`（插件的真实依赖）与 `wit/`，不是 `crates/ide-plugin`（宿主侧）：

- `API_VERSION`：`"1.15"` → `"1.18"`。
- WIT 全部 `package openidea:plugin@1.15.0` → `@1.18.0`。
- **新增**（无删除）：`pick-file`、`open-terminal-session-in`、`vcs_roots`、`vcs_repository_at`、
  `subscribe_paths_with_options`、`watch_paths`、`project_generation`、`start_run_with_options`、
  `fork_agent_session`、`set_markdown_decorations`、`set_styled_decorations`、`invoking_project` 等。
- **删除**：`API_VERSION` 常量被改值（不是删）、宿主侧的 `register_run_target` / `subscribe_paths`、
  某个 `ALL: [Self; 18]` 常量。**本仓三处都没用**（`grep -rn "register_run_target\|subscribe_paths" src/ tests/`
  零命中）。
- `host::reveal_view(&str)` 签名未变（1.15 在 `host.rs:1779`，1.18 在 `host.rs:1906`，签名逐字相同）。
- `views::ViewEvent` 仍是 `Button/Activate/Select/Expand/Collapse/Field/Cell/InsertRow/DeleteRows/Message/Other`，
  本仓只用到 `Button(String)` 与 `Message(String)`，两种都在。
- 1.18 新增 `ViewEvent::closed()` 辅助方法（`views.rs:321`，判定 `Other { kind: "closed" }`），
  这是第 3 节 C／升级清单里「关弹窗清状态」那步要用的 API，**它是新增的，不是改签名**，所以现有代码不受影响。

按提交看，1.18 是这几条能力叠加的结果：`bfbc70a43`（1.17 编辑器装饰配色）、`2bbba9b94`（overlay 浮层）、
`ce03ae7c0`（run 配置要 PTY/管道）、`e3f9049e2`（项目目录里开终端 / Run Anything）、
`0101d11ac`（补全 run 配置 Arguments 字段）。

## 5 切换真正要动的东西

`scripts/upgrade-plugin-api.sh` 改的是**六处**，四个文件：

| 文件 | 处 | 形态 |
| --- | --- | --- |
| `plugin.toml` | 1 | `engines.openidea = "^1.15"` |
| `Cargo.toml` | 1 | `openidea-plugin = { git = ..., tag = "v0.1.51" }` |
| `build.yml` | 2 | `CLI_TAG: v0.1.51` + `grep -F "0.1.51" /tmp/cli-version.txt` |
| `release.yml` | 2 | 同上两行 |

工作流的两处是一件事的两个写法：`CLI_TAG` 决定下载哪个版本的 CLI，`grep -F` 断言解出来的二进制
确实那个版本。只改前者不改后者，工作流会「装 0.1.51、要求 0.1.54」，在 `set -e` 下必红；只改
`build.yml` 不改 `release.yml`，发版那条腿照样红。所以脚本按 `grep -F` 的**形状**锚定
（`^grep -F "<x.y.z>"`）而不是按旧版本号锚定，改了以后仍能重入。

脚本仍然覆盖不到、要手工处理的：

1. `Cargo.lock`：改 `Cargo.toml` 不会自动重解析 git 依赖。可以 `--update-lock` 让脚本顺带跑
   `cargo update -p openidea-plugin`（联网，几十秒；默认不跑，`--dry-run` 下强制不跑）。
2. 注释里那句 `# Exactly 0.1.51: ...`（两条工作流各一处）与 `Cargo.toml:15-16`
   「Building against `main` targets API 1.16」——后者已经不是事实（main 是 1.18）。脚本把这类
   prose 列出来但**不改**，因为它不编辑叙述。
3. `scripts/README.md`、`AGENTS.md`、`docs/registration/L10.md` 里的 `0.1.51` 叙述。
4. `plugin.toml` 的 `engines.openidea` 是 `^1.18` 之后，`^1.15` 时期写的清单键（`docs/开发计划`
   §C2 的 `scripts/check-manifest-api.sh`）才有意义——那是另一条车道。

脚本对「没认出来的断言」不是沉默：写完会重扫工作流，凡**非注释行**还写着旧 CLI 版本号的，打
`WARNING: these workflow lines still name an old CLI version and are not comments` 并给出
文件与行号。干净仓库跑完不会打这条（实测 0 次）。

## 6 方法上的两点

- **「编不过」要先分清 target**。同样是 `--all-targets`，wasm 下 47 红、宿主下 0 红，差别全在
  `#[cfg(not(wasm32))]` 门住的测试桩。不区分 target 就把这 47 条写进「升级风险」是错的结论。
- **判据用同一份工作树做对照**，不要跨版本推理。基线 47 error 与 1.18 的 47 error 逐条对齐，
  这比「SDK 没删东西所以应该没问题」有力得多。
