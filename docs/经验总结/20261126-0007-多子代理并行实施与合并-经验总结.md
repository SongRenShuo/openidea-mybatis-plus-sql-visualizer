# 多子代理并行实施：车道、注册制与合并清理

> 归属：跨任务复用（多车道并行交付一套插件）。

## 1 目录所有权是防冲突的第一道闸

只有主控能改的单点文件：`plugin.toml`、`src/lib.rs`、`Cargo.toml/lock`、`README.md`、
`locales/*.json`、CI。子代理只写 `docs/registration/<lane>.md`，由主控合并后统一应用。
效果：12+ 条车道并行，唯一的共享文件冲突只出现过一次（`src/commands/mod.rs`），
且由后合并方按 master 结构重排解决。

## 2 骨架先落地，车道不再碰模块声明

主控先建好 `src/core/mod.rs` 与 `src/lib.rs` 的全部 `pub mod` 占位，车道只在自己目录内新增文件。
否则每条车道都要改 `lib.rs`，必然冲突。

## 3 注册分次落地，最后出一份单点清单

基础层、MCP、捕获分三次应用注册（每次都能立刻 `check` 验证），最后用
`docs/registration/SUMMARY.md` + `chore: 注册汇总（最终清单）` 收拢。分次不等于漏项，
但要有一份终态快照供人复核。

## 4 合并点固定动作

`git merge --no-ff` → 本地 `cargo test` + `openidea-plugin build && check` →
推 `ci/gate-<n>` → 用 `gh run view --json conclusion` 判绿 → 再删 worktree/branch。
删分支前必须 `git merge-base --is-ancestor`；CI 未绿就删分支会丢修复线索（本轮发生过一次，
从提交哈希重建分支修完才正式删）。

## 5 子代理报告要可核

要求报告含：改动文件、门禁读数原文、提交哈希、`git status --short`、注册片段路径、遗留。
出现「全量绿」而它只跑过定向测试的，按未跑处理。

## 6 收尾两条容易漏的车道

- **命令接线**：引擎写完了不等于用户能用；要单独一条车道把命令 -> 引擎接上并改掉 P0 固定输出。
- **真实入口验收**：Find Action 不传参数，带参命令需要菜单/状态栏入口，否则 GUI 验收不了。

## 7 并行上限

同时编译的车道建议 ≤6；主仓 gradle 与另一个 gradle 车道错开。派完立刻做下一件事，
靠 task-notification 继续，不 sleep 轮询。
