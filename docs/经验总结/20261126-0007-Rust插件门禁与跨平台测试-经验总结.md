# Rust 插件仓的门禁与跨平台测试坑

> 归属：跨任务复用（Rust/wasm 插件仓的提交、门禁、测试）。

## 1 车道本地门禁不含 clippy，推 CI 前必须补一次

车道只跑 `cargo fmt --check` + 本模块测试。CI 的 `cargo clippy --all-targets -- -D warnings`
会拦下 `collapsible_if`（用 let-chain）、`manual_map`、`dead_code`、`bool_comparison`、
`redundant_closure`、`saturating_sub` 等。实测 L2/L3/L4/L6 都因此多跑了一轮 gate。

配方：合并点或推 `ci/gate-*` 前，本地跑一次

```sh
cargo clippy --all-targets -- -D warnings 2>&1 | tail -20
echo "CLIPPY_EXIT=${PIPESTATUS[0]}"
```

## 2 管道会吞掉退出码

`gh run watch … | tail`、`cargo test | tail` 的退出码是 `tail` 的 0。曾把失败的 CI 判成绿，
并据此提前删了分支。

配方：CI 结论只看 `gh run view <id> --json status,conclusion`；命令退出码用 `${PIPESTATUS[0]}`。

## 3 `#[path]` 不要放进内联模块

集成测试里这样写，基准目录会变成不存在的 `tests/commands/`：

```rust
mod commands {                     // 基准 = tests/commands/
    #[path = "../../src/commands/x.rs"] pub mod x;
}
```

Windows 容忍，Linux 拒绝（`couldn't read …/tests/commands/../../src/…`）。
配方：把 `#[path]` 放在文件顶层（基准 = `tests/`），再用 `mod commands { pub use … }`
聚合成命令树；或者给 `[lib] crate-type` 加 `"rlib"`，让集成测试直接 `use` crate。

## 4 MockHost 是线程局部的

用例只拿测试锁、不安装 MockHost 时，Windows 可能复用同线程上一个用例装的 host 而通过，
Linux 新线程直接 panic（`no mock host: call MockHost::install() first`）。

配方：**每个用例自包含**，第一行 `let host = MockHost::install();`；不要依赖线程复用。

## 5 edition 2024 的 `gen`

`src/core/gen/` 目录可以存在，但模块声明必须是 `pub mod r#gen;`，引用写 `crate::core::r#gen`。

## 6 rustfmt 与文件末尾换行

新文件若没有末尾换行，`cargo fmt --check` 会报 diff；统一先 `cargo fmt --all` 再提交。

## 7 测试分层与读数

- 单元测试写模块内 `#[cfg(test)]`，`cargo test <filter>` 可跑。
- `cases_parity` 读 `cases/cases.jsonl`，断言真实 SQL/字段，白名单条目要写理由并做 stale 检测。
- 报告写「跑了什么、多少判据」，不要写「全量绿」除非真跑过。
