# OpenIDEA 面板消息通道与真机验收经验总结

> 场景：OpenIDEA 端口（Rust/wasm 插件）进入全功能真机验收阶段，用 Computer Use 在真实 IDE 里逐项点验。
> 时间：2026-11-26 凌晨。涉及 13 条命令、两个面板、捕获链与设置页。

## 1 改完必须 `build` + 重启，否则看到的还是旧行为

- 现象：合并了「命令接受裸文件路径」的车道后，重启 IDE，右键 `check.sql` 执行「检查 SQL」，输出
  `class: UNKNOWN`，没有任何 `source:` 行；「打开工作台」把**文件路径本身**当成 SQL 显示在预览区。
- 误判方向：以为是 `sql_arg` 的路径判定写错了（读了半小时源码）。
- 真相：`plugin.toml` 的菜单是重启时从**清单**读的，所以 8 个菜单项立刻出现；但命令逻辑在 `dist/plugin.wasm`
  里，那次构建发生在合并之前 —— 清单是新的、wasm 是旧的。
- 判据：`ls -la dist/plugin.wasm` 的 mtime 与 `git log -1 --format=%ci <修复提交>` 对比；wasm 早于修复提交就是没生效。
- 记法：**清单变更看重启，代码变更看 build + 重启**，两者独立，别用「菜单出现了」推断代码是新的。

## 2 「页面 → 宿主」不通时，先找一条已经通的路做对照

- 现象：SQL 日志面板（代码绘制的 `Body::Html`）里，筛选框键入 `orders`、回车，行集仍 `1-6 / 6`；
  类别下拉切「错误」也不变。宿主侧 `handle_message` 的 `set-filter` 分支单测全绿。
- 走过的弯路：先补 `input` 防抖 + 回车立即应用（提交 `97892c5`），重构建重启后**依然不生效** —— 说明问题不在事件绑定。
- 对照实验：同仓的 `sqlv-workbench` 是 `web = "web/workbench.html"` 的**包页**，它的 `ready` → 宿主 `post_view_message`
  明显通了（页面拿到了本地化文案）。于是判断：同一平台下「包页」通、「Html body」不通。
- 结论：把面板改成包页（`web =`），宿主推 JSON、页面只建 DOM。这同时解决了渲染层的可维护性（布局全在 HTML/CSS 里改）。
- 记法：**遇到「消息发了没反应」，先做对照组**（同一平台里另找一条通的路），比读协议源码快得多。

## 3 `openidea-plugin check` 只校验清单引用到的文件

- 图标车道把 46 个工具栏 SVG 与插件 logo 复制进包，但没改 `plugin.toml` 时 `check` 依然 `ok` ——
  因为 `prepare()` 只清洗清单里声明的那几个路径。
- 反向验证的做法：在一个临时副本里把片段应用上去，`check` 变 ok；再把 `<script>` 注入 logo，`check` 必须变红
  （实测报 `icons/pluginIcon.svg: <script> is not allowed`）。两条读数都拿到，才算证明「校验面确实覆盖了这两个文件」。
- 附带发现：`install_package` 只复制**声明引用**的文件，没被引用的资产（那 46 个 SVG）不会进安装包 ——
  包页里要用的图标必须内联进 HTML，不能指望从 `icons/` 里引。

## 4 右键菜单参数是绝对路径，且不区分文件类型

- `projectView.context` 把选中文件的**绝对路径**作为命令参数（无引号、无 `@`），所以命令侧要接受裸路径。
- 同一份清单里 8 个菜单项对**任何**文件都显示（点 `pom.xml` 也能看到「回滚计划」）。原版是按文件类型过滤的；
  `menus` 支持 `when`（含 `workspaceContains:` 与插件自定义上下文键），但当前没有按扩展名过滤的现成键，
  需要 `host::set_context` 自己维护（记为 D2，未做）。

## 5 设置页与依赖设置的验收，卡在「输入进不去」

- OpenIDEA 的设置是独立的 Tauri 窗口。Computer Use 绑到该窗口后，坐标输入被平台拒绝
  （`independent_surface_requires_association`），AX 树只暴露插件市场列表、不暴露左侧导航，所以
  「已安装 → 本插件 → 42 个设置字段」这条路走不下去。
- 试过的手工替代：往项目 `.openidea/settings.toml` 写 `[plugins."<id>"]` + `"sql.dialect" = "PostgreSQL"`，
  重启后用 `check-sql` 探针读 `dialect:`，仍是 `(unset)` —— 该形状不被读取（写入后已还原备份）。
- 记法：**依赖设置的验收项（导航/注入/inlay/诊断）在自动化里是阻塞项**，要么补一条「设置写入」通道，要么人工走查；
  不要因为「命令都跑了」就把它记成通过。

## 6 真机读数比单元测试更容易抓到语义缺陷

- `render-log` 真机输出 6 条全 `duration=-`，而夹具里明明有 `<== Total: 1` 行 —— 单元测试覆盖了「能解析出条目」，
  没覆盖「耗时被回填」。连带的慢查询分类因此静默失效（记 D7）。
- `check-sql` 对含 `DELETE FROM users;` 的文件输出 `unbounded-write: no` —— 规则单测是绿的，因为它测的是单语句；
  多语句输入整体分析时规则没逐条命中（记 D4）。
- 记法：验收文档里「预期」要写到**具体数字与标记**（`duration≈5ms`、`unbounded-write: yes`），
  只写「输出摘要」会漏掉这类静默缺陷。

## 7 Computer Use 在这类 IDE 上的操作要点

- AX 树对 webview 暴露有限：可见列表项坐标可以大到 `y=9384`（虚拟化），**别拿它当屏幕坐标**；坐标必须取自最新一帧截图。
- 元素索引点击对 webview 内的输入框经常「接受了但没输入」，要**回读确认**（`textfield = orders` 才算输入成功）；
  实在不行就用坐标点击 + `typeText`，再回读。
- 主窗口的坐标点击可用；独立子窗口（设置）会被拒。截图 `emit:false` 只取帧、不刷屏。
- 切换窗口后要用 `list_windows` 拿新的 `window_id` 再绑定，否则「按下去了没反应」。

## 8 UI 复刻的正确起点是「读原版的骨架」，不是「照着截图调样式」

- 原版日志面板是 `JBTabs` 四页签 + 「顶部工具栏 / 筛选行 / 列表（色条 + 头部元信息 + SQL 行 + 错误行）/ 底部双通道状态栏」，
  不是表格、没有分页、没有常驻搜索框（搜索是 Ctrl+F 唤起的行）；类型筛选是带色块的**多选弹层**。
- 原版工作台是上下 `Splitter(0.4)`：上输入区（解析预览/格式化/从文件加载/清空），下预览区（参数左 / SQL 右 + 页签），
  方言**不是**面板控件（取设置，只显示只读标签）。
- 记法：先把原版的「容器层级 + 控件顺序 + 空态文案」抄成伪结构，再决定哪些能做、哪些要标「不支持」；
  照截图猜布局会做出「看着像、用起来不对」的东西。
