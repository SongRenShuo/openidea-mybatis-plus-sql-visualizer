# 核心流程详解

> 每条链路按「触发 → 解析 → 产出 → 落地」写，落点都给文件路径。
> 与 IntelliJ 版的差别只在平台接入方式，语义与 `confidence` 规则一致。

## 1 链路总览

| 输入 | 主链路 | 是否经引擎 |
| --- | --- | --- |
| Mapper XML | `commands/render_xml` → `core/xml` → `core/log` | 否 |
| Wrapper 链 / 注解 SQL / iBatis / JPA | `commands/*` → `sidecar` → 引擎 `renderLogs/checkSql` | 是 |
| 运行日志 | `commands/render_log` / `capture_open_log` → `core/log` → 面板 | 否 |
| 表结构 JSON | `core/gen`（CRUD、回滚） | 否 |
| EXPLAIN | `execute/explain` → 引擎包装 → `process:java` 起连接 | 是（引擎装配 + JDBC 执行在引擎侧） |

## 2 Mapper XML 渲染（`render-xml`）

1. `src/commands/render_xml.rs`：取参（`<path>`、`@<path>`、裸路径；可带 `#statementId`），读文件。
2. `src/core/xml/`：解析 `namespace`、语句节点、`resultMap`、`<sql>` 片段；`<include>` 先展开。
3. `src/core/xml/dynamic.rs`：对 `<if>/<choose>/<where>/<set>/<foreach>` 做**受限求值**——
   OGNL 只支持比较、空值判断、`and/or/not`；出现方法调用（如 `ids.size() > 0`）即判 `unresolved`，不猜。
4. `src/core/log/classify.rs`：语句分类（`SELECT/INSERT/UPDATE/DELETE/CREATE/DROP`）。
5. `src/core/params/`：`#{}` 换成 `?` 并按出现顺序产出参数占位表。
6. `src/commands/common.rs::emit`：写 Output 通道（200 KiB 上限，超出截断并带 `cmd.output.truncated`）。

输出形态：`-- <namespace>.<id> (confidence)` + SQL + `params: [...]`；`unresolved` 只输出 `-- reason [key]: …`。

## 3 引擎链路（Wrapper / 注解 / iBatis / JPA）

1. 入口：`check-sql`、`perf-advice`、MCP `sqlv_render_sql` 等。
2. `src/sidecar/proto.rs` 定义请求/响应（`renderLogs`、`checkSql`、`perfAdvice`、`explain.*`），**返回的是 `messageKey` 不是文案**。
3. `src/sidecar/` 启动 `engine/mpsv-engine.jar`（`--stdio` JSON 行协议），首次调用时 handshake；失败则返回
   `sidecar.unavailable`，命令降级为纯文本模式并在输出里说明。
4. 结果里的 `messageKey` 由本仓 `locales/*.json` 翻成文案（key → 文案是本仓职责）。

## 4 日志捕获

三条通道，优先级从高到低：

| 通道 | 实现 | 前置 |
| --- | --- | --- |
| Java agent + WebSocket | `src/capture/agent.rs` + `src/capture/ws.rs` | `process:java` + `net:127.0.0.1`；仅 Application / Spring Boot / JAR 运行配置 |
| 控制台桥 | `src/capture/console.rs`（插件注册的 `MyBatis SQL Visualizer` 通道） | `project.read` |
| 导出日志文件 | `src/capture/file.rs` + `capture-open-log` | 无（兜底） |

- 帧格式：`{type:"sql", payload:{...}}`，`WebSocketReady` 事件触发 `capture::bridge::on_websocket_ready(ctx)`（不轮询）。
- 断线重连：指数退避，连续 3 次失败降级到控制台/文件通道，并在状态栏写明。
- 端口固定 `capture.port`（默认 17890），agent 必须同端口。

## 5 日志面板数据流（`sqlv-logs`）

```
capture-open-log / capture 帧
   → log_panel::set_log_text  (store: 原始文本 + analysis)
   → build_rows(analysis, dedupe, expanded, slow_threshold)
        · 去重合并、同结构分组 ×N、N+1 标记、慢查询分档
   → host::refresh_view / post_view_message({op:"state", rows, filter, counts, labels})
   → web/log-panel.html 渲染 DOM（textContent）
   ← 页面回传 {op:"filter"|"copy-line"|"open-line"|"toggle-pause"|"clear"}
   → 宿主改状态 → 再推 state
```

- 状态字段：`rows[]`（`line/seq/time/duration_ms/rows_affected/dedupe_count/group_count/n_plus_one/source/method/sql/error_text/category`）、`filter`（类型集合、只看慢查询、关键字、大小写、正则、去重）、`counts`、`labels`。
- 宿主工具栏（暂停/清空/复制 SQL）走 `ViewEvent::Button`，与页面消息并列，两条入口都要维护。
- 缓冲上限由设置 `logs.pageSize` 决定（语义＝条数上限，不是分页大小）。

## 6 工作台数据流（`sqlv-workbench`）

```
open-workbench <sql|path|@path>
   → common::sql_arg（裸路径可读即当文件，否则当字面 SQL）
   → workbench::set_model + post_view_message({op:"load", model, labels}) + reveal_view
   → web/workbench.html 渲染（输入区 / 预览区 / 参数 / 页签）
   ← 页面回传 {op:"render"|"format"|"copy"|"export"|"clear"|"ready"}
```

- `ready` 是必要握手：页面加载完会要一次模型，宿主必须已经 `set_model`，否则空模型覆盖已有内容。
- 方言**不是**面板控件：取设置 `sql.dialect`，页面只显示只读标签。
- 「执行 SQL」不可用（平台 `database` 不执行、本插件也不执行用户 SQL），按钮禁用并说明 EXPLAIN 走引擎侧。

## 7 检查与性能

- `check-sql`：`classify_sql` → `perf::analyze` → 汇总 `class / dialect / destructive / unbounded-write / findings`。
- `perf-advice`：`core/perf/rules.rs` 的规则集（`missing_where`、`leading_wildcard_like`、`select_star` …）→ `score` + `breakdown`。
- 规则只输出 `rule_id` + `messageKey` + `severity` + 证据 JSON；文案在 locale 里。

## 8 CRUD 与回滚

- `generate-crud`：`core/gen/crud.rs`，输入 `{table, schema, columns, pk, dialect}`；主键列不进 INSERT，批量插入按两行样例。
- `rollback-plan`：`core/gen/rollback.rs`，输入 `{sql, table, columns, pk, dialect}`；产出
  `snapshot (run first)` + `reverse`；变更前镜像列缺值时给 `gen.rollback.before_image_required`，不假装能回滚。
- 方言标识符引用走 `core/dialect/`（PostgreSQL 用 `"`，MySQL 用反引号）。

## 9 导航、注入、inlay、诊断

| 能力 | 入口 | 说明 |
| --- | --- | --- |
| 导航 | `src/providers/navigation`（`textDocument/*` 类能力，平台按自己的接口） | 语句 id ↔ Mapper 方法；无 PSI，只能基于索引 + 文本匹配 |
| 注入 | `src/injections/` | XML 内 SQL 段高亮，宿主已有高亮时不重复 |
| inlay | `src/inlay_hints/` | INSERT 列清单、参数提示；无列清单不出 |
| 诊断 | `src/diagnostics/` | 未知列/参数缺失；无 schema 不误报 |

均受设置开关控制（`nav.enabled` / `injections.enabled` / `inlay.enabled` / `diagnostics.enabled`），
改完需重开文件（平台没有 provider 失效接口）。

## 10 MCP 工具

- 声明：`plugin.toml` 的 `[[contributes.mcpTools]]`（11 个 `sqlv_*`，schema 在包内）。
- 实现：`src/mcp/`，导出 `mcp-provider.call`；工具名 → `core` 或 `sidecar` 的入口。
- 纪律：`readOnly=true` 的工具绝不执行 SQL；`partial` 不得当 `exact` 返回；缺参/未知工具返回可读错误。
- 前提：IDE 内置 MCP 服务需启用，外部客户端连上才可见（验收文档 D6 记录该前置未接线）。

## 11 EXPLAIN（引擎侧）

- `execute/explain.rs`：拼 `EXPLAIN (FORMAT JSON)`（PostgreSQL）或 `SET SHOWPLAN_XML ON`（SQL Server），交引擎执行。
- 只支持只读语句；写语句直接 `explain.reject.writeStatement`，不发出请求。
- MySQL/MariaDB 不执行（驱动 GPL，许可不允许打包）。

## 12 常见问题速查

| 现象 | 先看 |
| --- | --- |
| 面板空白 / 不刷新 | 面板是否为 `web =` 包页；`ready` 握手有没有回 `state` |
| 页面按钮点了没反应 | 页面 `post` 是否被宿主 `handle_message` 收下（`Html` body 通道在 0.1.51 不通，见 D1） |
| 命令输出只有 `-- error [key]` | 参数形态：`<text>` / `<path>` / `@<path>`；裸路径含空格必须用 `@` |
| `unresolved` 太多 | OGNL 受限求值；方法调用一律不猜 |
| 引擎相关功能全灭 | `engine/ENGINE_VERSION` 与 sha256 是否匹配；`process:java` 是否被拒 |
| 改设置没生效 | 导航/注入类需重开文件；平台无 provider 失效接口 |
