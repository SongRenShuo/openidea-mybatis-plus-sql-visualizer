# 开发与测试指南

> 面向在这个仓里改代码的人。平台能力边界见 `docs/ARCHITECTURE.md`，流程细节见 `02-核心流程详解.md`。

## 1 环境准备

| 项 | 值 | 校验 |
| --- | --- | --- |
| Rust | 1.98.1，target `wasm32-wasip2`（`rust-toolchain.toml` 钉住） | `rustc -V`、`rustup target list --installed` |
| Node | 22.22.3（仓根 `.nvmdrc`，NVM Desktop 目录级切换） | `node -v` |
| CLI | `openidea-plugin` 0.1.51（API 1.15） | `openidea-plugin --version` |
| IDE | OpenIDEA 0.1.51 | 用于真机验证 |

CLI 常常不在当前 shell 的 PATH 上（Git Bash），可直接用绝对路径
`C:\Users\USER\.cargo\bin\openidea-plugin.exe`。

## 2 构建与运行

```bash
openidea-plugin build          # 产出 dist/plugin.wasm（约 1 MB）
openidea-plugin check .        # 校验清单、图标、schema、MCP schema（秒级）
openidea-plugin link .         # 把本仓链进 IDE（一次性）
```

要点：

- **改完必须 `build` 再重启 IDE**：IDE 加载的是 `dist/plugin.wasm`，只改源码不 build 等于没改（本轮踩过：菜单是新清单、代码还是旧的）。
- `plugin.toml` 改动（菜单、视图、图标、能力）在重启后生效。
- 新增 **required** 能力会让已 link 的插件**静默不加载**：先备份并补批准 `%APPDATA%\ai.l0ng.openidea\plugins\grants.json`，再强杀进程重启。
- `openidea-plugin pack` 不校验组件新鲜度：发布必须「先 build 再 pack」。

## 3 测试体系

| 层 | 位置 | 说明 |
| --- | --- | --- |
| 单元测试 | 各 `src/**/mod.rs` 的 `#[cfg(test)]` | 纯逻辑，一律不依赖 IDE |
| 集成测试 | `tests/*.rs`（`l8_parity`、`l11_commands`、`l16_arg_entry` …） | 经 `MockHost` 跑端到端命令 |
| 语义夹具 | `cases/` | XML/日志/Wrapper 的输入-期望对，`cases_parity` 逐条比对 |
| 引擎校验 | `scripts/verify-engine.sh` | 校验 `ENGINE_VERSION` 与 sha256；`--pin-only` 只校验 semver + 64 位 hex |

Mock 注意：

- `MockHost` 是**线程局部**的——多线程测试里忘了 `install()`，在 Windows 上可能复用同线程 host 而「假绿」，在 Linux 上 panic。
- `#[path]` 不能写在**内联模块**里（基准目录会算错，Linux 直接拒绝）；把聚合模块放顶层再 `pub use`。
- `crate-type` 必须同时有 `"cdylib"` 与 `"rlib"`，否则集成测试拿不到 lib。

进程级存储（面板行、workbench 模型、捕获会话、索引）的测试有两条硬规矩，违反任何一条都会得到
「本地绿、CI 红」的随机失败：

1. **一个存储只能有一把锁。** 现在面板行、workbench 模型与捕获会话共用
   `views::test_state_lock()`；`capture::bridge::test_guard()` 只是「拿这把锁 + 重置会话」的便捷
   包装，不再自带第二把锁。2026-11-27 的实例：`capture_poll` 的测试持捕获锁往面板追加一行，
   `capture_open_log` 的测试持视图锁数行数——并发下数到 3 行而不是 2 行，`ci/gate-30` 因此红，
   而本地连跑几轮都是绿。
2. **每个测试开始前统一重置，不靠「上一个测试会清」。** 用 `log_panel::reset_for_tests()` 这类
   共享重置函数，别在各自模块里手抄一份 `clear()`——漏掉某个字段（例如 `sources`）就会让断言
   依赖测试顺序。已经持锁的测试要调 `reset_capture_for_tests()`（只重置、不取锁）：同一线程对
   非重入的 `Mutex` 再取一次是**挂住**而不是报错，编译期看不出来。

第 1 条不是靠自觉：`test_state_lock()` 返回的 `StateLockGuard` 会记下本线程的持锁深度，
`log_panel::push_state()` 在测试构建里断言深度非零。每次 push 都会 `mem::take` 掉工作台的
one-shot `replace_input`/`handoff`，所以「不持锁就 push」等于偷走别人的标志，症状是在别的
用例里随机红（本轮两条 CI 失败都是这么来的）。有了这个断言，同样的错误会在本地当场红，并在
panic 信息里点名肇事调用。集成测试链接的是不带 `cfg(test)` 的 lib，不受影响。

## 4 门禁（分层，别越界）

| 层 | 在哪跑 | 内容 |
| --- | --- | --- |
| 车道内 | 本地 | `cargo fmt --all --check` + 只跑本模块测试（`cargo test <module>`） |
| 合并点 | 本地 | 一次 `cargo test`（增量）+ `openidea-plugin build && openidea-plugin check .` |
| 权威全量 | CI | `.github/workflows/build.yml`：`fmt` + `clippy -D warnings` + `test` + `build` + `check` + `scripts/verify-engine.sh` + 上传 wasm |

- 子代理**不跑**全量、不跑 clippy、不 `clean`、不 `--stop`；报告里不许写「全量绿」。
- 超过约 20 秒的命令一律后台跑，靠通知继续；禁止 `sleep` 轮询。
- 反向验证：守卫/扫描类改动要「临时摘掉修复 → 必须变红」，只造绿色样本不算证据。

## 5 扩展指南

### 加一条命令

1. `plugin.toml` 加 `[[contributes.commands]]`（`id` / `title` / `category`）。
2. `locales/en.json` + `locales/zh-CN.json` 加标题与文案（键 `command.<id>.*`）。
3. `src/commands/<name>.rs`：`run(ctx, arg)`，取参用 `common::sql_arg` / `json_arg`，输出用 `common::emit`，错误用 `common::report`。
4. `src/commands/mod.rs` + `src/lib.rs` 的 dispatch 接一行。
5. 加集成测试（`tests/`），跑 `cargo test` 与 `openidea-plugin check .`。

### 加一个面板或改面板

1. 面板 = `[[contributes.views]]`（`id/title/icon/location`），要页面就写 `web = "web/<page>.html"`。
2. 宿主侧实现 `Views::render`（代码绘制）或只实现 `Views::handle`（包页 + 消息）。
3. 包页自包含：内联 CSS/JS，只用 `--openidea-*` 变量，不引外链、不用 `innerHTML` 拼 SQL。
4. 规则：宿主推 `{op:"state", …}`，页面回 `{op:…}`；`ready` 必须回一次状态。

### 加一个 MCP 工具

1. `plugin.toml` 加 `[[contributes.mcpTools]]`（`name` / `description` / `inputSchema` / `readOnly` / `destructive`）。
2. schema 文件放包内，`$ref` 只允许本地片段。
3. `src/mcp/` 里登记实现，`readOnly=true` 的绝不写、绝不执行 SQL。

### 改引擎（`EngineApi` 门面、类型投影、方言表）

去 IntelliJ 仓 `sub-projects/engine-jar` 改，重新构建后在本仓升 `engine/ENGINE_VERSION` 与 `.sha256`。
本仓**不复制**引擎源码。

## 6 开发约定

- **不猜**：`exact/partial/unresolved` 三档必须有据；`unresolved` 不出 SQL。
- **错误一律带 key**：输出形如 `-- error [some.key]: 细节`，key 在 locale 里有文案。
- **`plugin.toml` 是单点注册文件**：并行开发时子代理只写 `docs/registration/L*.md` 片段，由主控统一应用。
- **提交**：中文、单一主题、`git commit -F <文件>`（禁 `-m` 带反引号，Git Bash 会吃掉内容）。
- **不擅自 push / 建 tag / 发 Release**。
- **图标**：SVG ≤16 KiB、禁 `foreignObject`/脚本/外链；视图图标只接受 IDE 内置名或包内 SVG（`views.icon` 只认前者时按平台为准）。
- **依赖**：许可白名单 Apache-2.0 / MIT / BSD；禁 GPL/AGPL（所以 MySQL 驱动不能用，EXPLAIN 只做 PG / SQL Server）。

## 7 并行开发铁律

- 一条车道一个 worktree（`.worktrees/lane-L*`）+ 一个分支（`feat/*`）；主工作树留给主控做真机验收。
- 同时跑构建的任务 ≤ 2 个（瓶颈是内存不是 CPU）；全量测试单路收口。
- 子代理开工前登记、跑完注销；撞锁记证据交回收口阶段，不许空等。
- 派活写死「每完成一件可提交的就立刻提交」；接手掉线代理前先 `git status` + 搜临时探针，确认工作树没停在「先红」中间态。

## 8 发布流程

1. `cargo test` + `cargo clippy -D warnings` + `openidea-plugin build` + `openidea-plugin check .` 全绿。
2. `openidea-plugin build` → `openidea-plugin pack`（顺序不能反）。
3. 记录包 sha256；本地签名（如启用）后写入注册表条目。
4. 注册表（`github.com/l0ng-ai/openidea-plugins`）：`publishers/<publisher>.toml` + `plugins/<id>.toml`，
   `package` 指向**已发布**的包 URL 与 sha256。
5. 用户明确授权后才 push / 建 tag / 提 PR。

## 9 上手路线

1. 读 `docs/架构设计/01`（分层）→ `02`（流程）。
2. 跑 `cargo test` 与 `openidea-plugin check .`，确认基线绿。
3. `openidea-plugin build && openidea-plugin link .`，打开一个带 Mapper XML 的项目，右键跑一遍 `render-xml` / `check-sql`。
4. 挑一条命令读通「`commands/*.rs` → `core/*` → Output」这条最小闭环，再动核心逻辑。
