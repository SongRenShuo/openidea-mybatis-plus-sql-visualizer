### 0.1 平台侧结论（决定了本轮的降级口径）

- SDK（v0.1.54 / API 1.18）**只有设置读**（`host::setting_bool/string/number`），**没有写设置、也没有「打开 IDE 设置页」的 API**。设置齿轮无法复刻原版「跳设置页」；本轮改为面板内「设置」弹窗（展示当前值 + 去设置页的路径说明），并写入 `LIMITS`。
- `database` 不执行 SQL：预览「执行 SQL」与「执行计划」真执行仍禁用（既有 LIMITS §3）；本轮只把按钮的存在感、禁用原因、tooltip 对齐原版。
- 设置 schema 支持 `boolean / integer / string / enum` 四种控件；颜色项用 `string` + `#RRGGBB` 说明，原版的颜色选择器不复刻（记 LIMITS）。
- 项目级设置（原版 `ProjectPluginSettings`）平台无对应 contribution，本轮不造；方言等按项目覆盖记 LIMITS。

## 2 前置：共享高亮模块（主控，已完成）

`web/sql-highlight.js`——两个页面共用的 SQL 词法器与渲染器：

- `tokenize(text)` → `{cls, text}[]`，token 类别与原版 `MP_SQL.*` 一一对应（kw/tbl/id/str/num/com/op/paren）；表名启发与 `AS` 别名窗口同原版。
- `into(element, text, limit=20000)` 用 `textContent` 构造 span，超长直接纯文本（日志摘要不会为一条两万字符的语句建几千节点）。
- `installStyles()` 注入 8 条样式，颜色绑宿主 `--openidea-*` 变量（原版绑 scheme key，同一语义策略；日志页「不用字面色」测试继续成立）。
- 自测：6 组词法用例通过（类名序列 + 拼接等于原文）。

## 9 MPJ 联表：从「悄悄丢结构」改成「明确不给 SQL」（2026-11-28）

用户贴出一条 MPJ 链的实机输出：

```
SELECT * FROM car_device_info WHERE id = 1
-- [wrapper.render.note] `.lambda` is not rendered by this version
-- [wrapper.render.note] `.selectAll` is not rendered by this version
-- [wrapper.render.note] `.leftJoin` is not rendered by this version
-- [wrapper.render.note] `.leftJoin` is not rendered by this version
```

`selectAll` 与两次 `leftJoin` 都被丢弃，SQL 却照常输出。这不是能力缺口，是**正确性
缺陷**：`SELECT * FROM car_device_info WHERE id = 1` 与原查询的行形状、列清单都不同，
页面把它当事实展示。

### 9.1 修法：把「不支持」分两档

| 类别 | 例子 | 结果 |
| --- | --- | --- |
| 决定行形状 / 列清单 | `selectAll` `selectAs` `select*` `selectCollection` `leftJoin` `innerJoin` `rightJoin` | `unresolved`，不出 SQL，原因 `wrapper.structural_method` |
| 只是少一个过滤条件 | `apply` `exists` `notExists` `having` | `partial`，照常出 SQL |

判据是「丢掉它之后，`SELECT * FROM 主表` 还是不是同一个问题」。

### 9.2 为什么不顺手把 join 补上

原版 `MpjLambdaConverter` 的 join 覆盖三参 / 四参带别名 / `on(col1, col2)` / lambda
ON / 5 参别名 + lambda / 子表 MConsumer 子查询 / `selectCollection` / `from(子查询)` /
`union` / `fill` 十余种形态，每种都要副表自己的 `TableInfo`（列展开 + 逻辑删除列）与
别名映射，并在 MPJ 官方输出上对拍。本仓无 PSI，副表信息要从实体文件读、别名按
「实体类名首字母小写」推定。**半套 join 比没有 join 更危险**：它会在部分形态上给出
看似完整、实则错误的 SQL，正是本次要消除的那类问题。

因此本轮先止损，联表列为独立任务（`docs/registration/L35a.md` §14.2 记了要覆盖的
形态清单）。落库前的替代出口已写进 LIMITS：用日志/历史里的真实语句，或直接粘 SQL。

### 9.3 新增测试

- `a_dropped_join_or_select_list_is_unresolved_not_partial`：就是用户这条链的形态，断言
  `unresolved` + 无 SQL + 两个 key 都在 `message_keys`。
- `every_join_family_loses_structure`：`leftJoin`/`innerJoin`/`rightJoin` 三者都不得渲染成
  单表语句。
- `a_select_list_alone_also_blocks_the_sql`：只有 `selectAs`、没有 `selectAll` 时同样不给 SQL
  （否则 `*` 会列出查询并不返回的列）。
- `a_condition_only_unsupported_method_stays_partial`：`apply`/`exists`/`notExists`/`having`
  仍是 `partial` 且有 SQL——钉住这条规则不能越界。

## 10 MPJ 联表渲染落地（2026-11-28，接 §9）

用户明确要求实现联表，并指出规格在原插件仓库（`MpjLambdaConverter` 及其

七个 service）里。§9 的止损（结构丢失不出 SQL）保留为兜底，本轮把能如实渲染的
形态全部补上。

### 10.1 语义对拍（以原版为规格）

- **A47 列自实体定别名**：ON 两侧与条件列都按「列自己的实体类」解析别名，移植
  原版修复的缺陷语义（`rightJoin(AreaDO.class, AreaDO::getId, AddressDO::getAreaId)`
  → `ON areaDO.id = addressDO.area_id`，`t.area_id` 是原版修过的真库报错）。
- **别名规则**：关联表 = 类名整体首字母小写（`AddressDO` → `addressDO`），主表 `t`，
  `setAlias("x")` 覆盖；四参 / 五参（右别名）显式覆盖。
- **SELECT 列表**：未显式指定时展开主表全部列（`t.col`，不是 `*`）；`selectAll(Class)`
  展开该实体列；`selectIgnore` 剔除；`selectAs` 的 AS 名取目标属性。
- **子查询**：`in/notIn/exists/notExists(Class, lambda)` 渲染为独立 SELECT
  （不继承主表别名，与原版一致）；子查询内含运行期参数时整链 `unresolved`。

### 10.2 实现要点

- `EntityColumns.related`：命令层扫链内 `X.class`，逐个 `resolve_class_path` +
  `parse_entity` 填充投影；副表不在索引 → `unresolved` 指名（不猜表名）。
- 限定列渲染拆段引用（`t.order` 不能整段 quote）。
- `WrapperContext` 透传 `related`：预览页条件勾选的重渲染自动带联表。
- 参数顺序：HAVING 参数排在条件后；子查询参数不内插（见 10.3）。

### 10.3 覆盖与不做的形态

覆盖（含 demo 全部七类场景）：三参/四参别名/五参右别名 join、lambda ON、`ext` 追加、
raw join 片段、`selectAll`/`select`/`selectAs`/聚合族（COUNT/SUM/MAX/MIN/AVG 带 AS）/
`selectIgnore`、`groupBy`/`having("…{i}…")`、`in`/`exists` 子查询、`setAlias`、
子表 MConsumer 子查询 join（`leftJoin(C, lambda, left, right)` 渲染
`LEFT JOIN (SELECT … FROM sub alias WHERE …) alias ON …`，子别名取 lambda 内
`setAlias`、无则类名首字母小写；子链带子别名重入渲染，ON 左列取子别名，
见 docs/registration/L35a.md §15.5）。

联表 UPDATE / DELETE（`JoinWrappers.update(C)`/`delete(C)`，原版
UpdateJoinConverter / DeleteJoinConverter 语义，见 docs/registration/L35a.md
§15.6）：SET 全族、删除目标四形态、整条语句渲染；SET 条目解析失败剔除并
partial，全部失败 unresolved。`in`/`exists` lambda 子查询含运行期参数时参数
就地嵌入（树序即 SQL 序，证伪了此前「文本层排不准」的前提，§15.7）。MPJ 方法
引用值槽一律列对列（原版 `simple()`），子查询内右列裸列。SELECT/FROM 侧六形态
（selectFunc/selectSub/selectCollection/selectAssociation/from/around，§15.8，
独立车道实施后合并）。

不做（`wrapper.structural_method` 不出 SQL）：`join("关键字")` 自定义关键字；
`selectSub`/`selectFunc` 子查询含运行期参数或 `{i}` 值、`selectCollection`
子/孙表不在投影（不猜表名）。
