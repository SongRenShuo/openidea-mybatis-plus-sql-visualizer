# Wrapper 条件能力对齐原版（全量）

> 立项时间：2026-11-29 02:24（03:10 改为全量版：原 §8「本轮不做」全部并入本轮）
> 触发问题：用户渲染包装器链时输出四条提示
> ```
> [wrapper.render.note] 包装器渲染说明（cannot map `StringUtils.hasText(query.getUsername())` to a column (field not in EntityColumns)）
> [wrapper.render.note] 包装器渲染说明（cannot map `query.getStatus() != null` to a column (field not in EntityColumns)）
> [wrapper.render.note] 包装器渲染说明（cannot map `query.getAge() != null` to a column (field not in EntityColumns)）
> [wrapper.unknown_field]
> ```
> 结论：**这是本版缺陷，原版对同一输入处理正确**。MyBatis-Plus 的 `condition` 首参可以是任意布尔表达式，
> 本版只认字面量 `true`/`false`，把 `StringUtils.hasText(...)`、`query.getStatus() != null` 这类**运行时布尔表达式**
> 当列名映射，失败即判 `unresolved` 并整条丢弃。
>
> 复盘时进一步发现：布尔首参只是**同一片能力缺失的冰山一角**。对照原版 `QueryWrapperParser` 的 `when` 分支全集，
> 本仓 `src/analyze/wrapper.rs` 缺 15+ 个官方 API 方法。**本轮一次性补齐**，目标是「Wrapper 条件渲染对齐原版」。

## 1 原版口径（对齐基准）

### 1.1 实参分类：`WrapperArg` 是类型化的

`model/WrapperChain.kt:113` 起，实参在 PSI 阶段已分型：

| 类型 | 含义 |
| --- | --- |
| `ColumnArg` | 列引用（`Entity::getX`） |
| `ValueArg(SqlValue)` | 值实参；`SqlValue` 分 `Literal`（静态可确定）与 `Placeholder`（运行时表达式/变量） |
| `NestedArg(WrapperChain)` | lambda 嵌套链 |
| `OnConditionArg` | MPJ `on(col1, col2)` |
| `MapArg` | `allEq` 的 Map 实参（`entries` + `null2IsNull`） |

**这是原版能做而本仓（wasm 纯文本解析）做不到的前提**：分类靠 PSI 类型而非字符串猜。下面的规则要**逐条翻译成文本判据**，不能照抄。

### 1.2 布尔首参的四处判定（规则出自原版，本仓要按族翻译）

**A. 条件族 `analyzeFlag()`**（`QueryWrapperParser.kt:786`）

1. 方法不在 `CONDITION_METHODS` → 不是标志
2. 首参是 `ColumnArg`/`NestedArg`/`OnConditionArg` → 不是标志
3. `asValue()` 取不到（非 `ValueArg`）→ 不是标志
4. arity：`UNARY_METHODS`(`isNull`/`isNotNull`) 要 2 参；`allEq` 要 ≥2；其余要 ≥3
5. **字符串字面量且内容非 `true`/`false` → 不是标志**（防 `between("create_time", …)` 把列名当布尔）
6. 其余（含 `Placeholder`）→ 是标志；`defaultEnabled = 非字面量 "false"`

**B. 分组族 `stripGroupFlag()`**（`QueryWrapperParser.kt:623`）
`GROUP_FLAG_METHODS = {and, or, nested, not, func}`；首参是 `NestedArg` → null；否则同 A 的 5/6 条。

**C. SET/join 族 `isFlagArgument()`**（`WrapperConverter.kt:367`、`LambdaUpdateConverter.kt:134`、`MpjLambdaConverter.kt:694` 三处同构）

1. `ColumnArg` → false
2. **`Placeholder` 且带 fragment（`asSqlFragment()` 非 null）→ false**（`setSql("a = " + x, …)` 的模板位不能被吞）
3. `Literal` → `unquoted` 是 `"true"`/`"false"`
4. `Placeholder` → true
5. 其他 → false

**D. `orderBy` 的布尔前缀**（`QueryWrapperParser.kt:249`，手写不走 `analyzeFlag`）
`orderBy(condition, isAsc, R...)`：先判 `condition`（同 A 的 5/6 条但**只认字面量**），再判 `isAsc`。

### 1.3 三档标注：`WrapperFlagOutcome`

`model/WrapperFlagOutcome.kt`，**纯只读探镜，零渲染行为变更**：

| 枚举 | 触发 | 中文 | 英文 |
| --- | --- | --- | --- |
| `ALWAYS_TRUE` | `flagSource == "true"` | 恒真 | always true |
| `ALWAYS_FALSE` | `flagSource == "false"` | 恒假 | always false |
| `DEFAULT_TRUE` | 其余非 null（运行时） | 恒真·缺省 | true by default |

tooltip：`布尔标志：{0} → {1}`。渲染点：条件行尾淡色标注（`SqlPreviewPanel.buildConditionRow`）。

**`DEFAULT_TRUE` 的设计意图必须保留**：MP 的 `condition` 缺省 true，预览按「成立」渲染；文案写「恒真·**缺省**」而非「恒真」，**是为了不让用户以为运行时表达式已被求值**。这是产品纪律「不猜」在 UI 上的落地。

## 2 本仓现状与根因

### 2.1 实测读数（先证伪再定性）

临时探针在 `src/analyze/wrapper.rs` 的 `mod tests`（`cols()` 为 `User`→`sys_user`，MySQL），读数实测、探针已删：

| 输入 | confidence | sql | keys |
| --- | --- | --- | --- |
| `eq(StringUtils.hasText(query.getUsername()), User::getStatus, "A")` | **Unresolved** | `None` | `wrapper.unknown_field` |
| `eq(query.getStatus() != null, User::getStatus, "A")` | **Unresolved** | `None` | `wrapper.unknown_field` |
| `isNull(query.getAge() != null, User::getAge)` | **Unresolved** | `None` | `wrapper.unknown_field` |
| `eq(true, User::getStatus, "A")` | Exact | `WHERE status = 'A'` | — |
| `eq(false, User::getStatus, "A")` | Exact | 无 WHERE | — |

### 2.2 根因

`src/analyze/wrapper.rs:2667` 的 `parse_leaf`：

```rust
if args.len() > base {
    match args.first().and_then(|a| parse_bool(a)) {
        Some(false) => return LeafOutcome::Skip,
        Some(true) => args = &args[1..],
        None => {}          // ← 运行时表达式落这里，首参原样留在 args
    }
}
```

`parse_bool`（`wrapper.rs:2748`）只认 `"true"`/`"false"`。运行时表达式没被剥掉 → 被 `resolve_column` 当列名 → `None` → `ctx.unresolved = true` + `push_key("wrapper.unknown_field")` + note → 整条链无 SQL。

三处判定（`parse_leaf`、`is_boolean_flag`、`and`/`or` 分支）**各写一套，全都不认运行时布尔**。

## 3 目标与口径声明

> **行为对齐原版，置信度按本仓纪律**。原版是 IDE 内实时预览、人眼即判，没有 `confidence`；本仓要出可执行 SQL，
> 运行时布尔按「成立」渲染而运行期可能为假，差异必须显式 → 降 `partial`。这与既有 `wrapper.param_value`
> （值按 `?` 渲染即降 `partial`）同一口径，**不是偏离原版**。

验收口径：

1. 用户三条输入变 `Partial` + 输出 SQL（条件按成立渲染），`wrapper.unknown_field` 不再出现。
2. 条件行尾出现与原版同文案的三档标注：`恒真` / `恒假` / `恒真·缺省`，tooltip 带首参原文。
3. §1.4 表中 15 项缺失方法全部有分发分支与渲染，各带测试。
4. `eq(true/false, …)` 回归不破。
5. `between("create_time", start, end)` 不被误剥；`setSql("a = " + x, …)` 不被吞。
6. 同一条链只出一条该原因提示；note 按 `(key, detail)` 去重。

## 5 各流实施步骤

### W1 布尔首参判定（基础设施）

**新建 `src/analyze/flag.rs`**：

```rust
/// 布尔条件首参的判定结果（原版 WrapperFlagOutcome 的解析侧等价物）。
pub enum FlagKind { AlwaysTrue, AlwaysFalse, Runtime }

/// 判定族：三族的排除规则不同（SET 族多排除带片段的运行时实参；
/// 条件族多认 isNull 的一元 arity）。
pub enum FlagOwner { Condition, Group, Set, OrderBy }

/// 统一判定，对齐原版 analyzeFlag / stripGroupFlag / isFlagArgument。
pub fn condition_flag(raw: &str, owner: FlagOwner) -> Option<FlagKind>
```

规则（按序短路，每条注明原版出处）：

| # | 形态 | 结果 |
| --- | --- | --- |
| 1 | `true` / `false` | `AlwaysTrue` / `AlwaysFalse` |
| 2 | 含 `::` | `None`（`ColumnArg` 排除） |
| 3 | 含 `->` | `None`（`NestedArg` 排除） |
| 4 | 字符串字面量且内容非 true/false | `None`（第 5 条） |
| 5 | `FlagOwner::Set` 且「字符串拼接形态」 | `None`（fragment 排除） |
| 6 | 其余 | `Runtime` |

**关键约束**：`Runtime` 只在 arity 表明「多了一个」时成立（复用各族 arity 表），不做独立语法判断——平台无类型系统，边界靠 arity 兜。

**改 `wrapper.rs` 三处**：

- `parse_leaf`（2667）：`match parse_bool(a)` → `match condition_flag(a, FlagOwner::Condition)`，`Runtime` 时 `ctx.partial = true` + `push_key("wrapper.condition_runtime")` + `Condition.flag = Some(Runtime)`
- `is_boolean_flag`（1227）：改为委托 `condition_flag(raw, FlagOwner::Set)`；`AlwaysFalse` 显式丢 SET 项
- `and`/`or` 分支（1030）：`args.join(",")` 前先判首参

**`Condition` 加字段** `pub flag: Option<FlagKind>`（`wrapper.rs:223`）。

**测试**：见 §6 W1 行。

1. 每完成一件可提交的就**立即提交**（`git commit -F <文件>`，禁 `-m` 带反引号）。

4. 计划 §9 的回写**只改自己工作树里的副本**，主仓副本只读。
