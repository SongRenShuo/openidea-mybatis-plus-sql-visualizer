### 踩坑：cargo 的 git 依赖在本机拉不动

`cargo fetch` 拉 `github.com/l0ng-ai/openidea` 时，libgit2 连续三次
`[28] Timeout was reached (Operation too slow. Less than 10 bytes/sec…)`，仓库对象 406 MB，
1 分钟只下到 13 MB。Git CLI 本身通（`git ls-remote` 正常），所以问题在 cargo 的内置 git 传输与网速，
不是网络不通。现场处置（不改仓内任何文件）：

1. 用本地已有克隆播种 cargo 的 db：`git clone --bare file:///F:/code/Java/Github/other/openidea
   ~/.cargo/git/db/openidea-7faf5f9c9e6a9886`；
2. cargo 离线解析要的是**远程跟踪引用**，补建 `refs/remotes/origin/tags/<tag>` 与
   `refs/remotes/origin/<branch>`（否则报 `reference 'refs/remotes/origin/tags/v0.1.51' not found`）；
3. 再正常 `cargo fetch` 拉 crates.io（34 个包，秒级），之后 build 直接命中。

供后来者参考的通用解：`CARGO_NET_GIT_FETCH_WITH_CLI=true`（让 cargo 走系统 git），或长期写进
`~/.cargo/config.toml` 的 `[net] git-fetch-with-cli = true`。CI（ubuntu-latest）不受此影响，未加本地配置。
