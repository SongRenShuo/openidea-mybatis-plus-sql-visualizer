### 13.3 顺带发现：两处「别的插件做过」的可行性证据

1. **官方 `openidea.mybatis`（MyBatis Navigator 0.4.2，`plugins/official/mybatis`，1700 行 Rust）**已经实现：mapper 接口 ↔ XML 语句/resultMap/sql id 双向跳转、gutter 箭头、**`#{}` 参数与语句 id 补全**，`kinds = ["definition","line-markers","completion"]`、`languages = ["java","xml"]`。这直接证明 F17/F18/F21 与 F03/F06 在本平台可行；同时说明**编辑器集成面已有官方竞品**，本仓的差异化必须落在「渲染出可执行 SQL」上，不宜在补全上做超越式投入。
2. **平台支持的 provider kinds 比本仓用到的多**：`README:1435` 列出 `definition` / `line-markers` / `completion` / `inline-completion` / `code-actions` / `semantic-tokens` / `hover` / `inlay-hints` / `diagnostics`（本仓在用 `definition`、`hover`、`gutter-actions`、`injections`、`inlay-hints`、`diagnostics`），`plugins/official` 里还有插件在用 `code-lenses`。高亮与折叠类需求可考虑 `semantic-tokens`，补全可直接用 `completion`，不必继续加注入或自绘。

## 16 最值得优先修的 5 条

1. **C06 参数区没有参数名**（P0）。现在只显示「序号 + 文本框」（`web/preview.js:678-712`），而原版显示 `#source` 并带类型提示。这是「预览能不能用」的分水岭：用户看不出哪个框对应哪个条件，填错值也不知道。修法：渲染链把 `#{}` 名透传到 `WorkbenchModel`，页面按名渲染。
2. **C07 + C14 条件与拦截器语义缺失**（P0）。XML `<if>` 无法逐个开合、MyBatis-Plus 的逻辑删除/多租户/分页完全不参与渲染。原版把这三样当核心卖点（`panel.condition.*`、`settings.injectLogicDelete`…）。修法：`src/core/xml` 已有条件节点树，给 `WorkbenchModel` 加 `conditions[]`；拦截器语义在 `render.rs` 里按设置追加子句。
3. **A02 排序只有 2 项**（P0，用户已实测点名）。7 项里缺的 5 项（耗时降序、捕获序、结构聚类、数据库分组）都是纯排序逻辑，`SortMode` 枚举扩到 7 个 + 页面换下拉，工作量小、感知强。
4. **J02/J04/J07 三处「实现有、入口无」**（P1）。`core/annotation.rs`、`core/ibatis/`、`analyze/wrapper.rs` 都写完了、有测试，但没有任何命令/provider/MCP 调用它们——这是全仓最大的沉没成本。修法：`preview-sql` 按来源分派 + `sqlv_render_sql` 支持 `kind`。
5. **A11 屏蔽规则无持久化、无对话框**（P1）。现在 `block_line` 只把行号塞内存（`src/views/log_panel.rs:1572-1590`），重启即丢；原版有 500 条上限的规则库 + 结构匹配 + 管理对话框。修法：`storage` 存规则数组、按 SQL 指纹匹配、加一个管理页（复用设置页的 web 面板形态）。

> 附：如果不修第 1 条，第 2 条的价值会打折——两者都落在参数区，建议同一车道（W2-2）一次做完。
