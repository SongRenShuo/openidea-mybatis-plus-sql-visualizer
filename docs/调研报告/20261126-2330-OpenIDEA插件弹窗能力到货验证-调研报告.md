# 20261126-2330-OpenIDEA插件弹窗能力到货验证-调研报告

> 验证对象：上游 issue [#6012](https://github.com/l0ng-ai/openidea/issues/6012)（本仓 2026-11-26 提交的「插件 API：开放自定义浮层窗口」）
> 与其实现 PR [#6178](https://github.com/l0ng-ai/openidea/pull/6178)（模态对话框）、[#6046](https://github.com/l0ng-ai/openidea/pull/6046)（浮层）。
> 结论一句话：**能力已在 `main` 落地，但一个已发布版本都还不含它；现在动不了，等 1.18 发布。**

## 1 上游答复原文要点

维护者（`l0ng-ai`，OWNER）在 #6012 下的回复，2026-11-26T12:18Z：

- **模态对话框**：`plugin.toml` 声明 `[[contributes.dialogs]]`（`id` / `title` / `web` / `width` 320–1600 / `height` 200–1200）；
  插件代码在 gutter 动作或快捷键命令里调 `views.reveal(id)`，就在当前窗口弹出带平台标题栏的模态对话框。
  可调整大小（按对话框记住尺寸），关闭按钮或 Esc 关闭；页面可调 `openidea.dialog.close()`。
  关闭时插件收到 `closed` 视图事件，页面与插件之间的消息与普通 web 视图相同。
- **浮层**：`[[contributes.overlays]]`，非模态、不抢焦点的浮动页面（xirf 贡献，PR #6046）。
- 插件需把 `engines.openidea` 提到 `^1.18`。

issue 状态 `closed / completed`（2026-11-26T12:18:04Z）；#6178 `MERGED`（2026-11-26T12:18:02Z，合并提交 `9c9e0e59`），#6046 `MERGED`（12:11:04Z）。

## 2 能力核实（源码级）

| 断言 | 证据 |
| --- | --- |
| 扩展点真的注册了 | `crates/ide-host/src/plugins/ui_points.rs`：`pub const DIALOGS: &str = "dialogs";`、`pub const OVERLAYS: &str = "overlays";`，并有 `dialog()` / `overlay()` 两个校验函数 |
| 尺寸与字段约束 | `dialog()`：`DIALOG_WIDTH 320..=1600`、`DIALOG_HEIGHT 200..=1200`；`DialogDecl { id, title, web, width, height }`，`deny_unknown_fields` |
| 与工具窗 id 不能重名 | `dialog()`：`declarations(VIEWS)` 里有同名 `id` 直接报 `a view has the same id` |
| 强制 API 1.18 | 两处都调 `pkg.manifest.needs_api("contributes.dialogs", 18)`；`needs_api` 见 `crates/ide-extension/src/manifest.rs`，低于 1.18 就报 `is new in plugin API 1.18` |
| 打开方式 | SDK `host::reveal_view(id)`（`sdk/rust/openidea-plugin/src/host.rs`），前端 `src/features/plugins/views/dialog.tsx` 里 `views.reveal` 先认 dialog 再认工具窗 |
| 关闭事件 | SDK `ViewEvent::closed()`（`sdk/rust/openidea-plugin/src/views.rs`），匹配 `kind == "closed"` |
| 页面侧关闭 | 页面可用 `openidea.dialog.close()`；该全局只在 dialog 的页面里注入 |
| 不需要新能力 | 文档与源码都写明「sees nothing of the IDE, so it needs no capability」 |

编译级验证（不只看文档）：用 `branch = "main"` 的 SDK 建了一个最小 crate，调 `host::reveal_view`、`ViewEvent::closed()`、`API_VERSION`，
`cargo check --target wasm32-wasip2` 通过（`Finished dev profile`，0 error），SDK 解析到 `13c0e8aa`，`API_VERSION = "1.18"`。

## 3 关键限制：现在用不了

| 事实 | 读数 |
| --- | --- |
| 已发布最新版 | `v0.1.53`（2026-11-26T04:09Z），`API_VERSION = "1.17"` |
| 次新 | `v0.1.52` → `1.16`；我们钉的 `v0.1.51` → `1.15` |
| `v0.1.53` 的 `ui_points.rs` | 没有 `DIALOGS` / `OVERLAYS` 常量（grep `dialogs` 计数 0） |
| `v0.1.53` 的插件文档 | `plugins/README.md` 无 `contributes.dialogs`，API 变更节最高到 `### API 1.17` |
| 本机 IDE | `D:\RuanJian\OpenIDEA\openidea.exe` FileVersion `0.1.53` |
| 本机 CLI | `openidea-plugin 0.1.51 (plugin API 1.15.0)` |
| `main` 相对 `v0.1.53` | 领先 93 个提交（`gh api compare`） |
| 用 0.1.51 CLI 校验含 `[[contributes.dialogs]]` 的清单 | `warning: contributes.dialogs: not supported by this version of the IDE; skipped`，其余 `ok`（不报错，静默跳过） |
| 跳过行为的实现 | `v0.1.53` 的 `crates/ide-extension/src/registry.rs:259`：未知扩展点走 `not supported by this version of the IDE; skipped`；`:591` 有对应测试 `invalid_declarations_fail_prepare_and_unknown_points_warn` |

所以：**清单写了 dialogs，在 0.1.53 里不会报错，只会被跳过**——不弹窗、也不提示失败。这比报错更危险：真机验收会得到「什么都没发生」，
容易误记成我们的实现 bug。反过来，若把 `engines.openidea` 提到 `^1.18`，0.1.53 直接拒绝装载（实测 CLI：`"^1.18" does not match this IDE's plugin API 1.15.0`）。

## 4 对本仓的影响与建议

1. **现在不动代码**。`engines.openidea` 保持 `^1.15`，`LIMITS.md` 第 22 条「没有插件可用的模态对话框 API」暂时保留，但要补一句「上游 1.18 起提供，
   等发布后升级」，免得读者以为永远没有。
2. **升级是一次小版本跳跃，不是一行改动**：`^1.15 → ^1.18` 跨三个 minor，含 `frames`/`markdown_hover`/`customEditors.binary`（1.16）、
   `Run Anything`、PTY 输出、`Project::generation()`、`EventKind::ProjectClosed`（1.18）等；SDK tag 要同步从 `v0.1.51` 换到含 1.18 的 tag（**目前还没有这个 tag**），
   `openidea-plugin` CLI 也要换成 1.18 对应的版本。CI 的 `CLI_TAG`、`Cargo.toml` 的 tag、`rust-toolchain.toml` 三处一起动。
3. **弹窗改造的真实收益**：原版 `SqlPreviewDialog` 是模态窗，用户在弹窗里看 SQL、调参数、复制。本仓现在落在 `SQL 预览` 页签（右侧工具窗第 5 页），
   功能等价但没有「随手弹出、看完就关」的体验。1.18 到位后，`preview-sql` 命令可改为 `reveal_view("<dialog-id>")`，页签形态保留给「常驻对照」场景；
   浮层适合做「捕获中」的常驻小指示。
4. **不要用浮层冒充模态**：`[[contributes.overlays]]` 不抢焦点、尺寸 40–800，做不了带标题栏的可调窗口，验收口径别混。
