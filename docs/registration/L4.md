## locales 键（供 T2-4 / L5 落文案）

核心只返回点号小写 message_key，文案由 i18n 层提供：

| key | 含义（中文建议） |
| --- | --- |
| `log.entry.params_missing` | 占位符多于参数，未能还原全部 `?` |
| `log.entry.params_unused` | 参数多于占位符，多余参数未使用 |
| `log.entry.sql_truncated` | SQL 超过解析长度上限被截断 |
| `log.entry.multiline_unclosed` | 多行 SQL 块未闭合，已保留残句 |
| `log.entry.raw_preserved` | 原文已保留在 raw_line |
| `log.entry.sql_missing` | 错误行，未产出 SQL |
| `log.unparsed.orphan_parameters` | Parameters 行没有对应的 Preparing |
| `log.unparsed.orphan_preparing` | Preparing 行没有可解析的 SQL |
| `log.unparsed.unrecognized_sql` | 像 SQL 但没有家族能识别 |
| `log.unparsed.sql_too_long` | 行文本过长（预留） |

## 消费入口（L5 面板 / L9 MCP）

```rust
use core::log::{parse, LogAnalysis, ParseOptions};
let analysis: LogAnalysis = parse(text, &ParseOptions::default());
```

- `entries` 按 `line_no` 升序；`slow` / `errors` 是 `entries` 的副本，用 `line_no` 对回。
- `duplicates` / `n_plus_one` 为分组结果，`line_nos` 可直接跳行。
- `confidence` 遵循架构 §4：`unresolved` 的 `sql` 恒为空，只给 `raw_line` 与原因键。
- 四个家族：`mybatis` / `p6spy` / `hibernate` / `jdbc_template`（枚举 `Family`）。

## 与参考仓的差异（需在合并说明中保留）

参考仓没有独立的 p6spy SQL 解析器：p6spy 只出现在 `LogDurationParser`
（`ts|ms|statement|sql`）与 `ExecutionTimeParser`（`elapsed N ms`）。本车道据此实现 p6spy 家族；
参考仓的第四个独立解析器是 ShardingSphere（`Logic SQL:` / `Actual SQL:`），不在 T1-11 的四族内，
本车道未实现。iBatis 2.x 的 `{pstm-N}` 三行组属于 MyBatis 家族的扩展形态，T1-11 未要求，亦未实现。
