# L16 注册申请（命令的项目视图右键入口）

本车道让除 `capture-open-log` 以外的带参命令也能从项目视图右键调用。右键菜单会把**当前选中
文件的路径**作为命令参数传进来（无 `@` 前缀、无引号），所以本车道同时让命令接受「裸路径」形态：

- `sql_arg`（`check-sql` / `perf-advice` / `open-workbench`）：`@<path>` 照旧；新增裸路径——
  参数不含空白字符且能通过 `Project::read_file` 读到文件时，文件内容即 SQL；读不到就按字面
  SQL 处理。含空白的参数**永不**尝试读文件，所以 `UPDATE user SET name = 'x'` 不会被误判为路径。
- `json_arg`（`generate-crud` / `rollback-plan`）：`@<path>`、裸路径 JSON 文件、行内 JSON 三种
  形态；仍保留 `cmd.json.invalid`（非法 JSON 照旧报这个 key）。

本车道只提交注册片段，不改 `plugin.toml`（该文件由主控独占）。

## plugin.toml — 项目视图右键菜单

在已有的 `capture-open-log` 菜单项之后追加（`capture-open-log` 已注册，**不要重复**）：

```toml
[[contributes.menus]]
menu = "projectView.context"
command = "render-xml"

[[contributes.menus]]
menu = "projectView.context"
command = "check-sql"

[[contributes.menus]]
menu = "projectView.context"
command = "perf-advice"

[[contributes.menus]]
menu = "projectView.context"
command = "generate-crud"

[[contributes.menus]]
menu = "projectView.context"
command = "rollback-plan"

[[contributes.menus]]
menu = "projectView.context"
command = "render-log"

[[contributes.menus]]
menu = "projectView.context"
command = "open-workbench"
```

## 每个命令从右键拿到的参数

| command | 右键传入 | 说明 |
| --- | --- | --- |
| `render-xml` | 选中 XML 的路径 | 无 `#statement` 时渲染文件内全部语句；原本就按路径工作。 |
| `check-sql` | 选中 `.sql` 的路径 | 文件内容作为 SQL 分类与安全/性能检查输入，输出 `source:` 行。 |
| `perf-advice` | 选中 `.sql` 的路径 | 本轮把 `perf-advice` 从「只认行内 SQL」改为走 `sql_arg`，输出 `source:` 行。 |
| `generate-crud` | 选中 JSON 的路径 | 文件内容是 `{table,columns,pk,dialect}`；行内 JSON 形态仍然可用。 |
| `rollback-plan` | 选中 JSON 的路径 | 文件内容是 `{sql,table,columns,pk,dialect}`。 |
| `render-log` | 选中日志文件的路径 | 原本就按路径工作（`capture-open-log` 的同一输入形态）。 |
| `open-workbench` | 选中 `.sql` 的路径 | SQL 作为工作台初始内容，`source` 记为该路径。 |

## 已知限制（建议写进菜单/文档说明）

- 裸路径判定要求**参数不含空白字符**：Windows 上路径含空格（如 `C:\My Files\a.sql`）时会被
  当成字面 SQL。这类路径仍可用 `@<path>` 形式（`@` 分支先 trim 再按完整路径读取，路径内部
  的空格没问题）。
- `json_arg` 的裸路径在文件不存在时会退化为「字面 JSON」解析，因此报 `cmd.json.invalid`
  而不是「文件不可读」；`@<path>` 形态对缺失文件报 `cmd.file.unreadable`。

## 无新增命令、能力、locale 键

菜单项只引用已注册的命令 id，不需要新增 `[[contributes.commands]]`，也不涉及 capability、
`src/lib.rs` 或 locale 文案。
