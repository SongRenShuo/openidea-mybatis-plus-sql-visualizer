## plugin.toml — 顶层 logo

放在文件头部（`version` / `description` 附近的顶层键区，与 `id`、`name` 同级，不是任何 `[[contributes.*]]` 块内）：

```toml
icon = "icons/pluginIcon.svg"
# icon-dark 不声明（2026-11-27 用户口径 + 原版核实修正，见 §资产表下方）
```

根据 SDK 0.1.51 源码（`crates/ide-extension/src/manifest.rs`）：

- `icon-dark` 必须与 `icon` 同时出现，单独写 `icon-dark` 报 `` `icon-dark` needs `icon` ``；
  两条路径都必须是包内相对路径（`check_relative`）。
- 这两个 SVG 会随 `prepare()` 一起进包（`crates/ide-host/src/plugins/mod.rs` 的 `prepare`），
  并由 `read_icon(pkg, path, MAX_SVG)` 过白名单清洗：允许的元素/属性覆盖本车道用到的全部
  `rect` / `circle` / `line` / `path` 与 `fill` / `stroke` / `stroke-*` / `rx` / `x1`…；
  `foreignObject`、`script`、外链一律拒绝。文件上限 `MAX_SVG = 64 KiB`，实际两个文件各不足 1 KiB。
- **只在这一处补这两行之后**，`openidea-plugin check .` 才会真正读取并清洗这两个 SVG
  （`prepare()` 里 `plugin_icon(pkg)` 只校验清单声明的那两个路径）。本车道未改 `plugin.toml`，
  所以这两条要到主控应用后才进校验面。

## 工具栏资产的可用范围（重要，后续车道先读这段）

`icons/toolbar/` 46 个文件已就位，但按 SDK 0.1.51 的实现，**它们眼下既不会进安装包、也无法直接
当视图按钮图标**：

1. **不被声明引用就不进安装包。** 安装只复制声明引用到的文件：
   `install_package(src, target, files, hash)` 逐个 `files` 复制，
   `files` 来自 `prepare()` 的 `PreparedSet.files`（"Package files the declarations reference"）。
   本车道新增的 46 个工具栏 SVG 目前没有任何声明引用，`build`/`pack` 之后安装目录里不会有它们。
   后续车道要么让某个声明（视图/标记/文件图标/hover-action）指到具体文件，要么在补上引用之前
   别假设运行时能取到。
2. **视图按钮的 `icon` 是 IDE 内置图标名，不是包内路径。** `sdk/rust/openidea-plugin/wit/views.wit`
   的 `record button`：`/// An IDE icon name (refresh, add, remove, run, …). icon: option<string>`。
   所以日志面板/工作台工具栏那排按钮要靠平台内置图标名（`refresh`、`run`、`copy`…），
   原版的这些 SVG 无法一一照搬。真正接受「声明过的清单 SVG 路径」的 API 面是
   `hover-actions.wit`（`icon: option<string>`，注释写明 "a registered icon name or a declared
   manifest SVG path"）和 `language-features.wit` 的 gutter/hover 图标。
   把这些 SVG 用起来的最短路径是先加 `[[contributes.markerIcons]]` 或 hover-action 声明。

保留这批文件的价值：图形与配色与 IntelliJ 原版一一对应，等 API 面能接包内 SVG 时直接引用，
不必再去原版仓找。

## 校验（本车道实测）

哈希核对比两处，避免「行尾」把结论搞成假绿或假红：

1. **工作树文件级**（复制当时）：46 个工具栏 SVG + `sqlLog.svg` + `sqlGutter.svg` 与源文件
   `sha256` 逐一相同，逐字节一致。原版仓 `.gitattributes` 是 `eol=crlf`，所以检出的是 CRLF；
   本仓是 `eol=lf`，`cp` 过来的 CRLF 在 `git add` 时按 `* text=auto eol=lf` 归一成 LF。
2. **仓库 blob 级**（提交后，行尾归一后）：48 个文件的 `git show HEAD:<path>` 与
   原版仓 `git show HEAD:src/main/resources/<path>` 的 `sha256` 全部相同，0 处不符。
   也就是说两个仓里存的是同一份字节，差只差在检出策略。

logo 两个文件：

- 几何与着色内容与源逐行相同，只删掉了源文件里的 XML 注释（原注释写的是 IntelliJ 渲染器的
  实现细节与「不放在 META-INF」的历史约定，在 OpenIDEA 端口里是误导；而且清洗时注释本来就会被丢弃）。
  去掉注释后与源 blob 比对 `sha256` 相同（亮色 `cb67d2e5eb77…`、暗色 `4ca58a42b727…`）。
- 无 `foreignObject` / `<script>` / `http(s)://` 外链，`viewBox="0 0 40 40"`，`width`/`height` 均为 40，
  各不足 1 KiB（远低于 `MAX_SVG = 64 KiB`）。

本车道没改 `plugin.toml`，为了不把这两条片段留在「没跑过校验」的状态，另做了一次一次性探针：

- 把包复制到临时目录（`plugin.toml` + `dist/plugin.wasm` + 引用到的 `icons/`、`web/`、`engine/`、
  `agent/`、`src/`、`locales/`、`settings.schema.json`），在副本里补上顶层 `icon` / `icon-dark`
  两行，`openidea-plugin check .` 输出 `ok`（exit 0）——这两条片段与两个 SVG 是真能过闸的。
- 同一副本再把两个视图 `icon` 换成 `icons/sqlLog.svg` / `icons/sqlGutter.svg`，`check` 仍 `ok`。
- 反向验证（证闸门真读 SVG，不是空绿）：在副本的 `icons/pluginIcon.svg` 末尾塞
  `<script>alert(1)</script>`，`check` 立刻红：

- 探针目录用完即删，工作树里没有残留；`plugin.toml` 始终未改。
