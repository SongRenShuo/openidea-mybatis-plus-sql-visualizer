# L9 注册申请（feat/mcp）

车道 L9 交付 11 个 MCP 工具的声明、dispatch 与 handler：

- 代码：`src/mcp/**`（`mod.rs`、`contract.rs`、`handlers/*.rs`、`schemas/*.schema.json`、`tests.rs`）
- 清单：本文件下方的 11 条 `[[contributes.mcpTools]]`
- 导出：`register_plugin!(Main, mcp);`

本车道不新增能力，不执行任何 SQL，也不写数据库：全部工具 `readOnly = true`、
`destructive = false`（生成类只出文本，`explain` 只格式化调用方给的结果）。

## capabilities

无新增。

- 所有参数由调用方传入（XML 文本、日志文本、SQL、表结构、EXPLAIN 结果），工具本身不读项目文件、
  不起进程、不连数据库、不访问网络。
- 生成类工具（`crud_sql` / `rollback_plan` / `reverse_sql`）只返回文本，`readOnly = true`；
  `explain` 只格式化调用方已经拿到的结果，同样不执行。
- 因此 `destructive` 对 11 个工具一律为 `false`，不存在写库路径；`plugin.toml` 现有
  `required = ["project.read"]` 不变。

## locales 键（新增，需主控落 `locales/*.json`）

错误契约里的 `message_key` 统一由 i18n 映射；本车道新增以下键（其余复用 L1/L3/L4 的键）：

| key | 含义（中文建议） |
| --- | --- |
| `mcp.error.invalid_arguments` | 工具参数缺失、类型错误或超出大小限制 |
| `mcp.error.unknown_tool` | 未知工具名（附可用工具清单） |
| `check.unbounded_write` | UPDATE/DELETE 无 WHERE（文本级判定） |
| `check.destructive_ddl` | DROP/TRUNCATE 会删除数据或对象 |
| `mapper.result_map.not_found` | 语句引用的 resultMap 未声明 |
| `log.parse.no_entries` | 日志文本没有解析出任何语句 |
| `engine.explain.unavailable` | 未提供 EXPLAIN 结果（本版不执行 SQL） |

复用键：`xml.include.not_found`、`xml.statement.not_found`、`xml.statement.duplicate`、
`xml.file.unparseable`、`xml.mapper.root_invalid`、`gen.error.*`、`gen.rollback.*`、
`gen.java.*`、`perf.*`、`log.*`。

## 工具行为与边界（评审用）

| 工具 | 后端 | 置信度口径 |
| --- | --- | --- |
| `sqlv_render_sql` | `core::xml::render_statement` / `MapperSet::render` | 透传 `RenderOutput.confidence`；`unresolved` 时 SQL 与 params 强制为空 |
| `sqlv_render_logs` | `core::log::parse` | 全部条目 unresolved → `unresolved`；任一条目非 exact 或有未解析行 → `partial`；否则 `exact` |
| `sqlv_check_sql` | 本车道轻量分类器 + `core::perf::analyze` | 恒为 `partial`（文本级，无 catalog/统计），绝不当 `exact` |
| `sqlv_perf_advice` | `core::perf::{analyze, score, index_advice}` | 文本可识别 → `partial`；不可识别 → `unresolved` |
| `sqlv_crud_sql` | `core::r#gen::crud` | `exact`（输入完整时确定性生成）；结构错误走错误契约 |
| `sqlv_rollback_plan` | `core::r#gen::rollback_plan` | 成功 `partial`（需 before-image）；无主键 → 错误契约 `unresolved`，**不给 SQL** |
| `sqlv_reverse_sql` | `core::r#gen::to_mybatis_plus_java` | 透传 `JavaCode.confidence`；`unresolved` 时 `code` 为 `null` |
| `sqlv_mapper_check` | `MapperSet::load` + 文本遍历 | 无 issue → `exact`；有 issue → `partial` |
| `sqlv_history_search` | 本车道逐行子串搜索 | `exact`（字面量搜索）；只搜入参 `text`，**不读 IDE 历史**（平台无该 API） |
| `sqlv_schema_context` | 本车道格式化 | `exact`（只格式化调用方给的结构） |
| `sqlv_explain` | 本车道格式化 | 有结果 → `exact`；缺结果 → `unresolved` + `engine.explain.unavailable`，**不伪造执行** |

错误契约（所有工具统一）：

```json
{"ok": false, "error": {"code": "...", "message_key": "...", "detail": ...}, "confidence": "unresolved"}
```

成功信封：`{"ok": true, "confidence": "exact|partial|unresolved", "data": ...}`；
`render_sql` 多文档分支额外带顶层 `issues`，日志无条目时额外带顶层 `message_keys`。

参数在 handler 内二次校验（`serde` + `deny_unknown_fields`）：必填缺失、类型错误、未知字段、
超过 1 MiB 均返回可读的 `invalid_arguments`，不 panic。`host::begin_task` 未使用——本版全部为
纯逻辑、单次调用远低于 5 s 预算，无需续期。

## 本地门禁读数（2026-11-25）

```
cargo fmt --all --check                              # 通过
cargo test mcp                                       # 24 passed, 0 failed
cargo clippy --all-targets -- -D warnings             # 本车道 0 条；命令整体 exit 101
                                                     # （余下全部来自 core/ 其他车道，未改）
openidea-plugin build .                              # dist/plugin.wasm 110.6 KiB
openidea-plugin check .                              # ok
```

说明：

- `cargo clippy --all-targets -- -D warnings` 的 40 条诊断全部落在 `src/core/**`
  （L1~L4 的 `collapsible_if` / `bool_comparison` / `dead_code` 等），`src/mcp/**` 为 0 条。
  把这些其他车道诊断临时 `-A` 掉再跑，命令 exit 0（证明本车道没有别的 lint）。
- 当前 `plugin.toml` 尚未加入 `mcpTools`（按车道纪律由主控在注册汇总时落），因此
  `openidea-plugin check` 还不会读取 schema 文件。本车道改用两道替代证据：
  `src/mcp/tests.rs` 逐个 `serde_json` 解析 11 份 schema 并断言 object /
  `additionalProperties=false` / ≤256 KiB / 无网络引用；另用
  `jsonschema` Draft 2020-12 `check_schema` 校验 11/11 通过。注册合入后
  `check` 会再走平台自带的 `jsonschema::validator_for`。
- `tests/l9_*.rs` 无法链接：本包 `[lib] crate-type = ["cdylib"]`，集成测试拿不到
  rlib。验收用例因此放在 `src/mcp/tests.rs`（与其他车道一致）。若主控需要
  `tests/` 下的集成测试，需在 `Cargo.toml` 把 `crate-type` 加 `"rlib"`（本车道无权改）。
