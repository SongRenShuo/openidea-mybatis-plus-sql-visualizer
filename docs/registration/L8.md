# L8 注册申请（feat/sidecar）

> 由主控在「注册汇总」时应用。L8 不拥有 plugin.toml / lib.rs / Cargo.toml / locales。

## plugin.toml — 能力

```toml
[capabilities]
required = ["project.read"]        # 已有：读源码/实体列映射
optional = ["process:java"]        # 新增（High，optional）：启动引擎 jar 做 Wrapper 渲染 / EXPLAIN 包装；
                                   # 用户拒绝时引擎不可用，插件降级为纯文本模式，其余功能照常。
```

**不声明 `net:`**：唯一的网络面是设置项 `engine.downloadUrl`，默认空。留空即不联网、不下载，
直接用本地 / 仓库 jar 或降级。若将来确定一个默认下载主机，再单独申请 `net:<host>`。

## plugin.toml — 设置

```toml
[[contributes.settings]]
key = "engine.downloadUrl"
type = "string"
default = ""
scope = "global"
title = "引擎 jar 下载地址"
description = "首次使用引擎时从此地址下载 jar 到插件私有目录，并用 ENGINE_VERSION.sha256 校验；留空则只用本地/仓库 jar，缺失时降级纯文本。"
```

## src/lib.rs

无改动：L8 不新增命令，也不导出 views/providers/indexing/diagnostics 等可选接口。
`sidecar` / `analyze` / `execute` 三个模块已在 `src/lib.rs` 声明。

## Cargo.toml 依赖

无新增（`serde` / `serde_json` 已在基线；SHA-256 为手写实现，不引 crate）。

## README 能力表

| 能力 | 风险 | 为什么需要 |
| --- | --- | --- |
| `process:java` | High（optional） | 启动 `mpsv-engine-<ver>.jar` 以渲染 Wrapper 链、生成 EXPLAIN 语句；缺省时降级纯文本，不影响读源码/解析能力。 |

## 引擎钉定与分发（请一并知悉）

- `engine/ENGINE_VERSION` = `0.1.0`；`engine/ENGINE_VERSION.sha256` =
  `7b04dfc26a985273c45a80076e7b938fd31062676891d5ae27ea06eb732a2d69`（加入 `StdioMain` 后重建 jar 实测）。
- jar 本体不入库；由 IntelliJ 仓 `sub-projects/engine-jar` 的 `jar` 任务产出
  `build/libs/mpsv-engine-0.1.0.jar` 与同名 `.sha256`。产物 manifest 带
  `Main-Class: mpsv.engine.StdioMain`，`java -jar <jar> --stdio` 即逐行收发 JSON。
- 运行期解析顺序：① `fs.plugin_dir()/mpsv-engine-<ver>.jar` ② 开发态仓库 `engine/…jar`
  ③ `engine.downloadUrl` 下载到 ①；下载后先校验 sha256 再启用。任一失败 → 文本模式 + message_key。
- 改引擎后的重钉流程：`./gradlew :engine-jar:jar` → `sha256sum` 新产物 →
  更新 `engine/ENGINE_VERSION.sha256` 与 `src/sidecar/mod.rs` 顶部钉值测试 →
  `bash scripts/verify-engine.sh <jar>` → `cargo test sidecar`。

## T5-7 对拍位置说明（重要）

- 5 类固定输入输出对拍（每类 ≥10 例）在 **`src/execute/parity.rs`（`#[cfg(test)]`）**，
  随 `cargo test execute` 运行。原因：本包 `[lib] crate-type = ["cdylib"]`，`tests/` 下的集成测试
  无法链接该 crate（`E0433 unlinked crate`），而 L8 无权改 Cargo.toml。
- `tests/l8_parity.rs` 只保留**不依赖 crate** 的 `#[ignore]` jar 端到端测试（仅 std + serde_json）：
  `MPSV_ENGINE_JAR=<path> cargo test --test l8_parity -- --ignored`。

## 遗留 / 风险

1. 引擎 jar 已补 `Main-Class: mpsv.engine.StdioMain`；`java -jar <jar> --stdio` 可逐行收发 JSON。
   sidecar `start()` 已按此启动并以 `{"kind":"ping"}` 握手；真进程往返见 §"实测读数"。
2. 引擎侧 `render` 仅覆盖 `logs`/`check`/`perf`；`wrapper`/`xml`/`annotation`/`jpa`/`jdbcTemplate`
   由 wasm 侧（L1/L8）解析，引擎返回结构化 `unresolved`（无 PSI）。
3. `explain` 只做语句包装（ExplainGate/ExplainSupport），不执行；`schema` 恒返回结构化
   `connection` 错误（引擎无 JDBC 驱动）。真正的执行/自省需持有连接的宿主补齐。（不变）

## 实测读数（真进程）

- `MPSV_ENGINE_JAR=<jar> cargo test sidecar -- --ignored --nocapture` →
  `real_jar_stdio_round_trip` 通过；**冷启 204–240 ms**（两次实测，spawn→ping 响应，目标 ≤2000 ms）。
- 同一测试内：`check` 往返 `statementCount=1` 且 `id=7` 回显；`explain` 返回
  `explainSql` 以 `EXPLAIN` 开头；坏 JSON 返回 `{"ok":false,"kind":"invalid"}` 且进程存活。
- 常规 `cargo test sidecar` = 36 passed / 1 ignored（即上述 e2e）。
