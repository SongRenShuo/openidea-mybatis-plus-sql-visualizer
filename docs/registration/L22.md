# L22 注册申请（SQL 日志面板：四页签结构与三个附加页签）

本车道把「SQL 日志」页（`web/log-panel.html`）从**单页面板**改成 IntelliJ 原版的
**单行页签结构**：`SQL 日志`（原页面原样保留）+ `日志 → SQL` + `SQL → Java` + `SQL 历史`。

> **不改 `plugin.toml`**。视图 id（`sqlv-logs`）、`web` 路径、命令、能力、MCP 工具都没变；
> `location = "right"`（侧边栏）由主控在 `7a6194f` 改好，本车道只读该文件。

## 1 页签结构

自绘 `tabstrip`（`id="tabStrip"`），形态对齐 IDE 的 JBTabs：单行、选中态下划线 + 底色、
溢出横向滚动（`overflow-x: auto`）。四个页签顺序与文案：

| 顺序 | 页签 | 文案键 | 面板 id |
| --- | --- | --- | --- |
| 1 | SQL 日志（默认选中） | `view.logs.tab.logs` | `panelLogs` |
| 2 | 日志 → SQL | `view.logs.tab.log_to_sql` | `panelLogToSql` |
| 3 | SQL → Java | `view.logs.tab.sql_to_java` | `panelSqlToJava` |
| 4 | SQL 历史 | `view.logs.tab.history` | `panelHistory` |

- 切换只切 DOM（`panel.hidden = !on` + 按钮 `.sel`），**不发状态请求**；`tab` op 只是提示，宿主不回推。
- 第一个页签的 DOM 完全保留（动作行 / 筛选行 / 搜索行 / 列表 / 空态 / 底部状态栏），功能没有删减。
- 日志列表的状态不丢：页面给推送的 `rows` 算一个轻量签名（`rowsSignature`），签名不变就**不重建列表**
  ——滚动位置、选中行、筛选条件都留在 DOM 里。所以 `log-to-sql` / `sql-to-java` / `history` 的回推
  不会打断左侧页签的浏览。
- 键盘：`Ctrl+Tab` / `Ctrl+Shift+Tab` 在四个页签间循环。**IDE 可能先吃掉这个组合键**（页面收不到），
  此时鼠标点击始终可用。

## 2 页面 → 宿主的 op

| op | 入参 | 行为 |
| --- | --- | --- |
| `tab` | `tab` | **no-op**：宿主接受、不回推（切页签是纯 DOM，不重新请求状态）。 |
| `log-to-sql` | `line`（可选） | 记住选中行并回推 `tabs.logToSql`。无 `line`＝最后一条语句；该行不是可还原语句时同样回退到最后一条。 |
| `sql-to-java` | `text`（`sql` 作为别名兼容）、`entity`（可选） | 调 `mcp::handlers::reverse_sql::run`（JSON 进 JSON 出），结果存进 `tabs.sqlToJava` 后回推。空文本＝清空结果。 |
| `history` | `keyword` | 调 `mcp::handlers::history_search::run` 搜**已捕获的日志缓冲区**，结果存进 `tabs.history` 后回推。空关键字＝清空结果，不调工具。 |
| `history-open` | `line` | 可还原语句 → `commands::open_workbench::run`（既有路径）；否则复制该行原文（优先用搜索结果里的文本，回退到缓冲区第 N 行）。 |
| `copy-code` | — | 把 `tabs.sqlToJava` 里的代码写剪贴板（页面拿不到剪贴板）。 |

复用既有 op，没有重造：`log-to-sql` 的「复制 SQL」用 `copy-line`，「发送到工作台」用 `open-line`
（两者本来就按 `line` 取该行可执行 SQL，与还原结果一致）。

## 3 宿主 → 页面（仍是 `{op:"state", …}`，原有字段全部保留）

新增一个 `tabs` 字段，三个页签各自独立，不污染日志行 state：

```
tabs: {
  logToSql: { empty, line, rawSql, params[], restored, confidence },   // 每次推送现算
  sqlToJava: { ran, code|null, confidence, reason, params[] },        // 缓存上一次转换
  history:   { ran, keyword, total, truncated,
               matches: [{ line, time, sql, text, has_sql }] }         // 缓存上一次搜索
}
```

- `logToSql.restored` 由 `core::log::restore_rendered(raw_sql, params)` 现算：复用
  `core/log/restore.rs` 的 `?` 扫描器（`restore_literals`），对**已渲染好的**参数做替换，
  不会二次加引号；与 `LogEntry::sql` 结果一致。
- `sqlToJava` 的 `code` 只取处理器 `data.code`；`data.code` 为空即为 `unresolved`，`reason`
  取 `data.unresolved[].message_key`（有多条时逐行）。处理器返回失败信封时 `reason` 取
  `error.message_key`，`confidence` 恒为 `unresolved`。
- `history.matches[].time` 由行号对上已解析的条目时间（无时间戳或非条目行显示 `-`）；
  `sql` 是该行还原后 SQL 的前 180 字；`has_sql` 决定点击是「发送到工作台」还是「复制原文」。

## 4 三个页签的最小可用形态

- **日志 → SQL**：上方「原始 SQL（? 占位）」+「参数（按顺序）」，下方「还原后的 SQL」；
  按钮「复制 SQL」「发送到工作台」；置信度徽标（精确/部分/未解析）；无行时显示
  `view.logs.tab.log_to_sql.empty` 空态并禁用两个按钮。
- **SQL → Java**：多行输入框 + 实体类名输入框 + 「转换」；显示生成的 Java、置信度、
  方法参数列表（`param1, param2 …`）；`unresolved` 不显示代码，只显示原因；「复制代码」。
- **SQL 历史**：关键字输入 + 「搜索」→ 列表（`#行号 · 时间 · [来源: -]` + SQL 预览），
  点一行发送到工作台（非语句行复制原文）；空态分「还没搜」与「没有匹配」两种文案。

## 7 未实现 / 已知限制（对用户可见）

1. **`SQL → Java` 没有「发送到工作台」**：工作台是 SQL 工作台，把 Java 塞进去没有意义，
   只提供「复制代码」。页签里不放空按钮。
2. **`SQL → Java` 多了一个「实体类名」输入框**：`sqlv_reverse_sql` 的入参是 `{sql, entity}` 且
   `deny_unknown_fields`，实体名是生成 `Entity::getX` 的必要信息。留空**不猜**，直接返回
   `unresolved`（`gen.java.entity_required`），页签显示原始原因键。
3. **未解析原因显示原始 key**：`gen.java.*`、`mcp.error.*` 这批键没有进 `src/i18n.rs`，
   `t()` 回退为键名——与工作台（L18）完全同口径；补译文属跨车道事项，本车道未擅自扩充。
4. **「SQL 历史」不是持久化历史**：平台没有 IDE 历史 API，本构建也不落盘（`docs/LIMITS.md` §5）。
   搜索范围＝**本会话已捕获的日志缓冲区**，清空面板后历史结果一并清空。
5. **没有「来源文件」列**：解析器不提供日志行的源码位置（`PanelRow.source/method` 恒空，见 L17），
   历史行显示 `[来源: -]`，不做假数据。
6. **`Ctrl+Tab` 可能被 IDE 抢占**：页面侧已实现循环，但组合键在宿主框架之前被消费时页面收不到；
   鼠标点击始终可用（登记在此，不宣称一定生效）。
7. **原版第五个「SQL 预览」页签未复刻**：本仓已有独立的 `sqlv-workbench` 视图承担该职责，
   重复挂一个页签会在两个入口间造成状态分裂。
8. `log-to-sql` 的选中行如果是错误行（无可执行 SQL），回退为「最后一条可还原语句」而不是空白。
