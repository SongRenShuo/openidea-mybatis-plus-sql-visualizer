### `.github/workflows/release.yml`

未在本机执行过（没有 tag、没有 secrets、也不允许在本轮发版），下面是**全文**，
按 `.github/workflows/build.yml` 的口径写（同一 CLI 版本、同一工具链、同一条
"CLI 拿不到就红" 的规则）。

```yaml
name: release

# Tag-driven only: a version tag is the single trigger, so a stray push to a
# branch can never ship a package. The tag is the manifest's version verbatim
# and carries no `v` prefix (`2026.11.28`), as the IntelliJ edition tags its
# releases; `[0-9]*` is what matches that shape. workflow_dispatch re-publishes
# an existing tag (assets are replaced, the tag itself is not moved).
on:
  push:
    tags: ['[0-9]*']
  workflow_dispatch:
    inputs:
      tag:
        description: 'Existing tag to (re)publish, e.g. 2026.11.28'
        required: true
        type: string

permissions:
  contents: write

env:
  CARGO_TERM_COLOR: always
  RUST_BACKTRACE: 1
  # Exactly 0.1.51: it pins the SDK tag (v0.1.51 → plugin API 1.15) that `build`
  # writes into Cargo.toml. A CLI built from `main` targets API 1.16, and no
  # released IDE loads such a component.
  CLI_TAG: v0.1.51

jobs:
  package:
    name: build + sign + verify
    runs-on: ubuntu-latest
    outputs:
      tag: ${{ steps.meta.outputs.tag }}
      package: ${{ steps.meta.outputs.package }}
      sha256: ${{ steps.pack.outputs.sha256 }}
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
          # workflow_dispatch can target a tag that is not the default branch.
          ref: ${{ github.event.inputs.tag || github.ref }}
      - uses: dtolnay/rust-toolchain@stable
        with:
          toolchain: 1.98.1
          targets: wasm32-wasip2
      - uses: Swatinem/rust-cache@v2

      - name: Install openidea-plugin ${{ env.CLI_TAG }}
        run: |
          set -euo pipefail
          curl -fsSL --retry 3 -o /tmp/openidea-plugin.gz \
            "https://github.com/l0ng-ai/openidea/releases/download/${CLI_TAG}/openidea-plugin-linux-x86_64.gz"
          gunzip -c /tmp/openidea-plugin.gz > /usr/local/bin/openidea-plugin
          chmod +x /usr/local/bin/openidea-plugin
          openidea-plugin --version | tee /tmp/cli-version.txt
          grep -F "0.1.51" /tmp/cli-version.txt

      # The tag is the release version; a mismatch would publish 0.1.0 under the
      # name v0.2.0 and make every later update decision wrong.
      - name: Tag must match plugin.toml version
        id: meta
        run: |
          set -euo pipefail
          tag="${{ github.event.inputs.tag || github.ref_name }}"
          top_level() {
            awk -v key="$1" '
              /^[[:space:]]*\[/ { exit }
              $0 ~ "^[[:space:]]*" key "[[:space:]]*=" {
                line = $0
                sub(/^[^=]*=[[:space:]]*"/, "", line)
                sub(/".*$/, "", line)
                print line
                exit
              }
            ' plugin.toml
          }
          plugin_id="$(top_level id)"
          version="$(top_level version)"
          if [ "$version" != "$tag" ]; then
            echo "::error::tag $tag does not match plugin.toml version $version"
            exit 1
          fi
          echo "tag=$tag" >> "$GITHUB_OUTPUT"
          echo "package=$plugin_id-$version.oiplugin" >> "$GITHUB_OUTPUT"

      # The key arrives base64-encoded so a trailing newline or CRLF in the
      # secret cannot corrupt it. It lives in $RUNNER_TEMP and is removed in an
      # `if: always()` step; it is never echoed, never in an artifact.
      - name: Publisher key
        run: |
          set -euo pipefail
          [ -n "${MPSV_KEY_B64:-}" ] || { echo "::error::MPSV_KEY_B64 is not set"; exit 1; }
          printf '%s' "${MPSV_KEY_B64}" | base64 -d > "$RUNNER_TEMP/publisher.key"
          [ -s "$RUNNER_TEMP/publisher.key" ] ||
            { echo "::error::MPSV_KEY_B64 decoded to an empty key"; exit 1; }
        env:
          MPSV_KEY_B64: ${{ secrets.MPSV_KEY_B64 }}

      - name: Build, sign, verify
        id: pack
        env:
          MPSV_KEY_FILE: ${{ runner.temp }}/publisher.key
          MPSV_PUBLISHER: ${{ vars.MPSV_PUBLISHER }}
          MPSV_OUT_DIR: dist
        run: |
          set -euo pipefail
          bash scripts/verify-engine.sh
          bash scripts/release.sh
          sha="$(awk '{print $1}' dist/*.sha256)"
          echo "sha256=$sha" >> "$GITHUB_OUTPUT"
          {
            echo "### ${{ steps.meta.outputs.tag }}"
            echo
            echo '```'
            cat dist/*.sha256
            echo '```'
          } >> "$GITHUB_STEP_SUMMARY"

      - name: Discard key
        if: always()
        run: rm -f "$RUNNER_TEMP/publisher.key"

      - uses: actions/upload-artifact@v4
        with:
          name: package
          path: |
            dist/*.oiplugin
            dist/*.sha256
          if-no-files-found: error

  github-release:
    name: GitHub Release
    needs: package
    runs-on: ubuntu-latest
    permissions:
      contents: write
    steps:
      - uses: actions/checkout@v4
      - uses: actions/download-artifact@v4
        with:
          name: package
          path: dist

      - name: Publish
        env:
          GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
          TAG: ${{ needs.package.outputs.tag }}
        run: |
          set -euo pipefail
          notes="$RUNNER_TEMP/notes.md"
          # No regex for the bracket in "## [x.y.z]": awk's `\[` escape is not
          # portable (gawk mangles it), so match by index() instead.
          awk -v ver="$TAG" '
            BEGIN { want = "## [" ver "]"; p = 0 }
            {
              if (p && substr($0, 1, 4) == "## [") exit
              if (index($0, want) == 1) { p = 1; next }
              if (p) print
            }
          ' CHANGELOG.md > "$notes"
          [ -s "$notes" ] || printf 'See CHANGELOG.md.\n' > "$notes"
          if gh release view "$TAG" >/dev/null 2>&1; then
            gh release upload "$TAG" dist/*.oiplugin dist/*.sha256 --clobber
          else
            gh release create "$TAG" --title "$TAG" --notes-file "$notes" \
              dist/*.oiplugin dist/*.sha256
          fi

      # Read it back from the release, not from the workspace: this is the only
      # check that proves what a user actually downloads.
      - name: Read back the published asset
        env:
          GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
          TAG: ${{ needs.package.outputs.tag }}
          EXPECTED: ${{ needs.package.outputs.sha256 }}
        run: |
          set -euo pipefail
          name="$(basename dist/*.oiplugin)"
          mkdir -p "$RUNNER_TEMP/download"
          gh release download "$TAG" --pattern "$name" --dir "$RUNNER_TEMP/download" --clobber
          actual="$(sha256sum "$RUNNER_TEMP/download/$name" | awk '{print $1}')"
          if [ "$actual" != "$EXPECTED" ]; then
            echo "::error::GitHub asset sha256 $actual != built $EXPECTED"
            exit 1
          fi
          echo "github: $actual ok"

  gitee-mirror:
    name: Gitee mirror
    needs: [package, github-release]
    runs-on: ubuntu-latest
    steps:
      - uses: actions/download-artifact@v4
        with:
          name: package
          path: dist

      - name: Upload the same bytes to Gitee
        env:
          GITEE_TOKEN: ${{ secrets.GITEE_TOKEN }}
          TAG: ${{ needs.package.outputs.tag }}
          OWNER: ${{ vars.GITEE_OWNER }}
          REPO: ${{ vars.GITEE_REPO }}
        run: |
          set -euo pipefail
          api="https://gitee.com/api/v5/repos/${OWNER}/${REPO}"
          release_id="$(curl -fsS --retry 3 "$api/releases?access_token=${GITEE_TOKEN}&per_page=100" \
            | jq -r --arg t "$TAG" '[.[] | select(.tag_name == $t) | .id][0] // empty')"
          if [ -z "$release_id" ]; then
            release_id="$(curl -fsS --retry 3 -X POST "$api/releases" \
              -d "access_token=${GITEE_TOKEN}" \
              -d "tag_name=${TAG}" \
              -d "name=${TAG}" \
              -d "body=See the GitHub release for notes." | jq -r '.id')"
          fi
          [ -n "$release_id" ] || { echo "::error::no Gitee release id"; exit 1; }

          for f in dist/*.oiplugin dist/*.sha256; do
            name="$(basename "$f")"
            # Re-runs must replace, not duplicate: drop same-named attachments.
            curl -fsS --retry 3 "$api/releases/${release_id}/attach_files?access_token=${GITEE_TOKEN}&per_page=100" \
              | jq -r --arg n "$name" '.[] | select(.name == $n) | .id' \
              | while read -r aid; do
                  [ -n "$aid" ] && curl -fsS -X DELETE "$api/releases/${release_id}/attach_files/${aid}?access_token=${GITEE_TOKEN}" > /dev/null
                done
            curl -fsS --retry 3 -X POST "$api/releases/${release_id}/attach_files" \
              -F "access_token=${GITEE_TOKEN}" -F "file=@${f}"
          done

      # The two mirrors must carry identical bytes; a re-packed asset on one side
      # is exactly the failure this step exists for.
      - name: Both mirrors must match the built sha256
        env:
          TAG: ${{ needs.package.outputs.tag }}
          OWNER: ${{ vars.GITEE_OWNER }}
          REPO: ${{ vars.GITEE_REPO }}
        run: |
          set -euo pipefail
          expected="$(awk '{print $1}' dist/*.sha256)"
          name="$(basename dist/*.oiplugin)"
          gh_url="https://github.com/${{ github.repository }}/releases/download/${TAG}/${name}"
          gitee_url="https://gitee.com/${OWNER}/${REPO}/releases/download/${TAG}/${name}"
          gh_sha="$(curl -fsSL --retry 3 --retry-delay 5 "$gh_url" | sha256sum | awk '{print $1}')"
          gitee_sha="$(curl -fsSL --retry 3 --retry-delay 5 "$gitee_url" | sha256sum | awk '{print $1}')"
          echo "built: $expected"
          echo "github: $gh_sha"
          echo "gitee:  $gitee_sha"
          [ "$expected" = "$gh_sha" ] || { echo "::error::GitHub asset differs from the build"; exit 1; }
          [ "$expected" = "$gitee_sha" ] || { echo "::error::Gitee asset differs from the build (re-upload, do not trust the first fetch)"; exit 1; }
```

### 关于索引，CI 刻意不做

`scripts/build-index.sh` 列举的是一个目录里的**所有** `.oiplugin`，而 CI 的工作区
只有当前 tag 的包。在这里重跑索引会把旧版本从索引里删掉，老 IDE 线立刻更新不了。
所以索引由维护者在本地按 `scripts/README.md` 重跑（`dist/` 留全部历史包），提交
`market/index.json` 后经 Gitee Pages 托管。这条是设计选择，不是遗漏。

## 需要的 secrets / variables

在仓库 Settings › Secrets and variables › Actions 里配置。缺任何一个，
`release.yml` 会红（不会降级成未签名包）。

| 名称 | 类型 | 内容 | 怎么生成 |
| --- | --- | --- | --- |
| `MPSV_KEY_B64` | secret | 发布者密钥文件的 base64（单行） | `base64 -w0 "$HOME/mpsv-publisher.key"`；与 `scripts/release.sh` 本地用的是同一把密钥 |
| `GITEE_TOKEN` | secret | Gitee 私人令牌，用途勾 `projects`/发行版相关权限 | Gitee › 设置 › 私人令牌；**该仓库必须在令牌的「选择仓库」范围内**，否则上传报 403 且文案是「无权限」 |
| `MPSV_PUBLISHER` | variable | `songrenshuo` | 与索引里登记的 publisher id 一致；缺省时 `release.sh` 回落到 `plugin.toml` 的 `authors[0]` |
| `GITEE_OWNER` | variable | Gitee 用户名/组织 | — |
| `GITEE_REPO` | variable | Gitee 仓库名 | — |

`GITHUB_TOKEN` 是自动的，不需要配置（`permissions: contents: write` 已声明）。

密钥纪律：`MPSV_KEY_B64` 一旦泄露就等于任何人都能冒充发布者签名；轮换时先在
索引里用 `--previous-key` 让新密钥被旧密钥背书，再换仓库 secret——顺序反了，
已装用户会因为「密钥变了」而拿不到更新。

## 两处资产 sha256 一致性检查（人工口径）

CI 里已经做了（`github-release` 与 `gitee-mirror` 各一步），人工复核用同一套读数：

```sh
# 1. 本地构建的读数
awk '{print $1}' dist/*.sha256

# 2. 两处下载物各自算一遍（不要复用本地文件）
curl -fsSL -o /tmp/gh.oiplugin  https://github.com/<owner>/<repo>/releases/download/<version>/<id>-<version>.oiplugin
curl -fsSL -o /tmp/ge.oiplugin  https://gitee.com/<owner>/<repo>/releases/download/<version>/<id>-<version>.oiplugin
sha256sum /tmp/gh.oiplugin /tmp/ge.oiplugin

# 3. 三处一致才算发布完成：本地 sha256 = GitHub 资产 = Gitee 资产
```

Gitee 的下载链接形式以发行版页面实际给出的为准：`.../releases/download/<tag>/<file>`
会 302 到附件地址，若该形态不可用，就从发行版页面复制附件链接再算 sha256，
并把实际形态记进 `scripts/README.md`。

## 风险与待验证

1. `release.yml` 未在本机跑过：无 tag、无 secrets，本轮明确禁止发版。首次真发版
   就是它的首次执行；`actionlint` 之类的静态检查本机也没装（不额外引入工具）。
2. Gitee 发行版 API 的附件字段名（`file`）与下载链接形态按公开文档写，未在真机
   验证；失败时的处置写在 `market/README.md` 的排查表里。
3. `gh release create --notes-file` 依赖 `CHANGELOG.md` 的 `## [x.y.z]` 段格式；
   段缺失时回落到「See CHANGELOG.md」，不会中断发布。
4. 索引重建不是 CI 的一部分（理由见上），所以「tag 推送后 IDE 里能看到新版本」
   还差一步人工操作——这一步现在是流程约定，不是自动化的。
