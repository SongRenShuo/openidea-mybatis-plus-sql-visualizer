# L15 注册申请（feat/explain-live，T5-5 收口）

本车道让引擎真连库执行 EXPLAIN，并把结果接到 Rust 侧。**没有**新增能力、命令、设置项、locale 键或
Cargo 依赖，`plugin.toml` / `src/lib.rs` / `locales` / `Cargo.toml` 均无需由主控改动。

## 1. 主仓（IntelliJ 仓 `feat/openidea-explain`，基于 `feat/openidea-port`）

只改 `sub-projects/engine-jar/**` 与根 `THIRD-PARTY-NOTICES.md`：

- `build.gradle.kts`
  - 新增 `org.postgresql:postgresql:42.7.1`（BSD-2-Clause，排除只服务编译期注解的 `checker-qual`）、
    `com.microsoft.sqlserver:mssql-jdbc:12.4.2.jre11`（MIT）。版本与主仓
    `gradle/libs.versions.toml` 的测试依赖同值，本机 Gradle 缓存已有，不引新仓库。
  - jar 打包：两个驱动各自带 `META-INF/services/java.sql.Driver`，`duplicatesStrategy=EXCLUDE`
    只会保留先到的一份（实测 SQL Server 驱动从 `DriverManager` 消失、报 "No suitable driver"）。
    改为排除依赖里的服务文件、由 `writeJdbcDriverServices` 写一份合并声明（PG + SQL Server），
    `DriverManager` 与 `Class.forName` 两条路都能用。
- `EngineApi.kt`：新增 `explainExecute(url, user, password, sql, timeoutMs)`。
  - 静态门：`SqlStatementSplitter` 只允许单条语句；`ExplainGate` 只放行 SELECT/WITH/VALUES/TABLE。
  - 已带 `EXPLAIN` 前缀的先剥掉（含 PG 选项串与 `ANALYZE`——`EXPLAIN ANALYZE` 会真执行查询）。
  - PG：`SET default_transaction_read_only = on` + `EXPLAIN (FORMAT JSON) <q>`；连接/语句均设超时。
  - SQL Server：同连接上 `SET SHOWPLAN_XML ON` + `<q>` + `SET SHOWPLAN_XML OFF`（只编译不执行）。
  - 成功 `{ok,format:"json"|"xml",plan}`；失败 `{ok:false,kind,messageKey,detail}`，
    kind ∈ timeout/permission/syntax/connection/other（拒绝类为 `rejected`，Rust 侧映射为 syntax）。
- `StdioMain.kt`：新增 `kind:"explain.execute"`（字段 url/user/password/sql/timeoutMs，缺省 5000 ms）；
  协议流改为**显式 UTF-8**——中文 Windows 上 JVM 的 `stdout.encoding` 仍是 GBK（JEP 400 只改
  `file.encoding`），带中文的数据库错误消息会输出 GBK 字节导致 Rust 侧 UTF-8 JSON 解析失败（实测）。
- `THIRD-PARTY-NOTICES.md`：新增第 5/6 节（PostgreSQL License 全文、mssql-jdbc MIT 全文），
  原「运行期平台依赖」顺延为第 7 节。

| SQL Server 2022 | `SELECT 1 WHERE 1 = 1` | `ok, format=xml, plan_len=1682` |

写语句拒绝（三库各一条）：`DELETE FROM …` / `UPDATE …` / `DROP TABLE …` →
`ok=false, kind=syntax, messageKey=explain.reject.writeStatement`，且未建连接。

**PG17 的库名偏差**：任务给的 `:20035/dbx_test` 在该实例上不存在——
`FATAL: database "dbx_test" does not exist`（3D000）。端口可达、凭据有效（同 pg16），
`/postgres` 可连且版本实测 `PostgreSQL 17.4 (Debian 17.4-1.pgdg120+2)`，故改用 `/postgres` 出结果；
没有自行建库（不在车道权限内）。

负向分类实测：错密码 → `kind=connection`（`28P01: password authentication failed`）；
不可达地址 2 s 超时 → `kind=connection`（`08001: Connection 尝试逾时。`，中文消息已按 UTF-8 正确解码）；
语法错误 → `kind=syntax`（`42601`）。查询级超时（SQLState 57014）无稳定的真机触发手段，
只由 `classifySqlError` 的单测覆盖，未在本轮真机触发。

## 5. 未验证项

Rust `run_live` 的进程内端到端（wasm 沙盒里 `host::start_stream`）未在本机跑：
本机无 wasm 宿主运行环境，且 `#[ignore]` live 测试依赖引擎 jar 的路径解析。
本轮真机证据来自「同一 wire 格式」的 `java -jar --stdio` 直灌（上面第 4 节），
Rust 侧的请求/响应/错误映射由单测覆盖。
