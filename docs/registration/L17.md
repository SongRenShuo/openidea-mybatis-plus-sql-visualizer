# L17 注册申请（SQL 日志面板：包页复刻 + 筛选修复）

本车道把 `sqlv-logs` 从**代码绘制的 `Body::Html`** 改成**包页**（`web = "web/log-panel.html"`），
按 IntelliJ 原版「SQL 日志」页签复刻界面与交互，并修掉缺陷 D1（筛选/类别切换不生效）。

根因（主控已确认）：旧实现的 `Html` body 里 `openidea.postMessage` 的「页面 → 宿主」消息没有到达，
所以输入关键字 / 切类别都不生效。改成包页后与 `sqlv-workbench` 走同一条已验证通路：
页面 `postMessage` 回传，宿主 `post_view_message` 下发完整状态 JSON。

本车道只提交注册片段，**不改 `plugin.toml`**（该文件由主控独占）。

## plugin.toml — 给 `sqlv-logs` 加 `web`

在已有的 `[[contributes.views]] id = "sqlv-logs"` 块里追加一行 `web`（其余字段不动）：

```toml
[[contributes.views]]
id = "sqlv-logs"
title = "SQL Logs"
icon = "icons/marker-statement.svg"
location = "bottom"
web = "web/log-panel.html"
```

> `web/` 目录与 `sqlv-workbench`（`web = "web/workbench.html"`）共用同一个根目录，允许：
> 宿主把 `web/` 下所有文件都算进两条声明的包内容（`web_files` 的规则）。

## 新增/改动文件

- `src/views/log_panel.rs`：整文件重写为「存 buffer → 解析 → 组装行 → 过滤 → 推送状态」；
  旧的 `build_html`/`row_html`/`paginate`/`Page`/`Throttle` 全部删除。
- `web/log-panel.html`：新增，自包含（内联 CSS/JS，全部用 `--openidea-*` 变量，无外链、无本地存储）。
- `src/i18n.rs`：新增 `view.logs.*` 文案（筛选行 / 状态行 / 右键菜单 / SQL 类型名）。
- `locales/en.json`、`locales/zh-CN.json`：同步新增同名 `view.logs.*` 键。
- `src/commands/capture_open_log.rs`：把「panel shows one page at a time」改为「panel buffer is
  capped at `logs.pageSize`」（分页语义已不存在），同步测试断言。
- `Cargo.toml` / `NOTICE`：新增 `regex`（MIT OR Apache-2.0，仅 `std` 特性）用于 `.*` 正则搜索。
  **这是本车道唯一的新依赖 → 属于「大改动」，发版前请主控跑一次 `verifyGate`/构建门禁。**

## 页面 → 宿主的 op（`ViewEvent::Message` 里的 JSON）

| op | 字段 | 含义 |
| --- | --- | --- |
| `ready` | — | 页面脚本就绪，请求下发全量状态（宿主回推 `op:"state"`）。 |
| `filter` | `types[]`、`types_mode`（`all`/`none`/`only`）、`slow_only`、`keyword`、`match_case`、`regex`、`dedupe` | 更新筛选并回推状态。`types_mode=all`＝「全部」、`none`＝「无」、`only`＝「N 项」。 |
| `page` | — | 兼容保留（当前无分页，等同重新推状态）。 |
| `toggle-pause` | — | 暂停/恢复实时刷新（暂停时宿主不再被 capture 刷新推状态，恢复后全量补上）。 |
| `clear` | — | 清空缓冲并回推。 |
| `copy-line` | `line` | 复制该行 SQL 到剪贴板。 |
| `copy-time` | `line` | 复制该行时间戳到剪贴板。 |
| `export` | — | 把当前可见（筛选 + 上限内）行的 SQL 落到 Output 通道。 |
| `open-line` | `line` | 双击行：复用 `open-workbench` 既有路径把该行 SQL 送进 SQL 工作台。 |

工具条按钮（宿主 `View.toolbar`）：`toggle-pause`、`clear`、`copy-all`（复制全部 SQL），
走 `ViewEvent::Button`，与页面 op 同名逻辑复用。

## 宿主 → 页面的状态（`host::post_view_message(VIEW_ID, json)`，`op:"state"`）

```
{
  op: "state",
  rows: [{
    line, seq, time, duration_ms, db, rows_affected,
    dedupe_count, group_count, n_plus_one, source, method,
    sql, error_text, category, sql_type
  }],
  filter: { types:[], types_mode, slow_only, keyword, match_case, regex, dedupe, regex_error },
  counts: { total, shown, slow, n_plus_one, truncated, cap },
  status: { console_lines, agent_connected, agent_events, paused },
  slow_threshold_ms,
  labels: { ... 全部本地化文案 ... }
}
```

- **状态里没有任何渲染好的 HTML**；页面用 `textContent` 建 DOM（SQL 不会被当 HTML 解析，防注入）。
- `category` ∈ `normal|duplicate|n_plus_one|slow|error`（文字/徽标着色轴）；`sql_type` ∈
  `select|insert|update|delete|create|drop|other|error`（左侧 3px 色条 + 「SQL 类型」多选着色轴）。
- `db`/`source`/`method` 目前日志解析器不提供，恒为空串，页面遇空段整段不显示。
  （IntelliJ 原版的 `[文件:行] [类#方法]` 需要栈帧来源，属后续车道。）

## 语义变化（需主控同步到验收文档）

- **不再分页**：页面不再出现 `1-6 / 6`，底部显示「共 N 条」；超过上限显示「已截断到上限 N」。
- `logs.pageSize` 语义改为**面板缓冲/显示上限（条数）**，键名保留不改；默认仍 50（可在设置里调大）。
  注意该键仍被 `render-log` 命令当作「每次输出条目数」，两处都理解为「上限」，共享默认值。
- 排序轴：左上「SQL 类型」多选按**语句种类**过滤（SELECT/INSERT/UPDATE/DELETE/CREATE/DROP），
  空选＝「无」＝不过滤任何行；「全部」＝六类全选（含 error/other）。左侧色条跟随 `sql_type`，
  文字强调色跟随 `category`（慢查询耗时用危险色、错误行用危险色）。

## 未实现 / 已知限制

- **`[MCP]` 徽标**：协议里没有「该行来自 MCP 工具」的标记，本轮不显示。
- **`[文件:行] [类#方法]`**：解析器无栈帧来源，`source`/`method` 恒空，页面自动省略。
- **右键「导出可见行集」**：已实现，落到 Output 通道（`MyBatis SQL Visualizer`，受现有 200 KiB 截断）。
- **N+1 / 去重徽标** 沿用 `build_rows` 既有字段；去重勾选复用既有解析器的 duplicate 分组。
- **暂停**：暂停时宿主跳过 capture 驱动的状态推送（画面冻结），恢复后一次性补推；筛选/清空等
  用户操作在暂停时仍会推状态（便于边暂停边查看筛选结果）。
- `logs.pageSize` 默认 50 作为「缓冲上限」偏小，建议主控按产品需要评估是否提高默认值（本车道未改默认）。

## 无新增能力 / 无新增命令

不改 `capabilities`、`src/lib.rs`、`[[contributes.commands]]`。包页只经 `openidea.postMessage/onMessage`
与宿主通信（无网络、无本地存储），符合平台对 `web =` 页面的限制。
