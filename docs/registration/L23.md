# L23 注册片段：SQL 预览并入日志面板第 5 页签

本车道把原独立视图 `sqlv-workbench` 收进 `sqlv-logs`，成为页签条第 5 项「SQL 预览」，
与原版 IntelliJ 插件一致（SQL 日志 ToolWindow 的第 5 个页签，而不是第二个 ToolWindow）。

`plugin.toml` 由主控独占，本车道**未改**。下面是主控需要删的整块，以及删后应有的读数。

## 1 删除的视图块

`plugin.toml` 内（注释与块一起删，或改写注释指向本文件）：

```toml
# Panels (L5). `sqlv-logs` is the package page; `sqlv-workbench` is the package page.
# The log window sits on the right, as the IntelliJ plugin's SQL Logs tool window.
[[contributes.views]]
id = "sqlv-logs"
title = "SQL Logs"
icon = "icons/sqlLog.svg"

[[contributes.views]]
id = "sqlv-workbench"
title = "SQL Workbench"
icon = "icons/sqlGutter.svg"
location = "right"
web = "web/workbench.html"
```

删掉的是**第二个块**（`id = "sqlv-workbench"` 起五行）。保留 `sqlv-logs`，只把上面那行注释改成：

```toml
# Panels (L5). `sqlv-logs` is the package page and carries the fifth tab, the
# preview workbench (lane L23).
```

同一次提交里再删文件 `web/workbench.html`（页面内容已并入 `web/log-panel.html` 的
`#panelPreview`；本分支留它是为了让 `check` 在 `plugin.toml` 未改的情况下仍能通过）。
删完后 `web/` 只剩 `log-panel.html`。

## 2 删后的读数

- `[[contributes.views]]` 计数 **2 → 1**，只剩 `sqlv-logs`（`location = "right"`）。
- `openidea-plugin check .` 的 views 项为 1；`web = "web/workbench.html"` 不再被引用。
- `icons/sqlGutter.svg` 若没有其它引用，可顺带从 `icons/` 移除（本车道未动，留给主控判断）。

## 3 宿主侧改了哪些东西

| 文件 | 改动 |
| --- | --- |
| `src/views/workbench.rs` | 删 `VIEW_ID`、`push_model`、`push_state(_with)`、`render_workbench`、`handle_workbench_event`、内联 HTML 页；新增 `preview_tab()`（`tabs.preview` 的载荷）、`select_tab()`、`request_tab()`、`note_page_tab()`、`request_input_replace()`、`handle_preview_message()`。模型、方言判定、渲染与 op 逻辑原样保留。 |
| `src/views/log_panel.rs` | `build_state` 增加 `tabs.preview` 与 `selectTab`；`handle_message` 认识 `preview` 前缀并转给 workbench，`tab` 用于清掉待切的页签请求；`Views for Main` 不再分发 `sqlv-workbench`。 |
| `src/commands/open_workbench.rs` | 设模型 → `workbench::request_tab()` + `request_input_replace()` → `log_panel::push_state()` → `reveal_view(log_panel::VIEW_ID)`；输出行改成 `sent to sqlv-logs#preview`。 |
| `src/capture/bridge.rs` | 删 `workbench_payload`（旧 `{op:"load"}` 形状）及其两条单测：它已无生产调用方。 |
| `src/i18n.rs`、`locales/en.json`、`locales/zh-CN.json` | 新增 `view.logs.tab.preview` = `SQL Preview` / `SQL 预览`。 |
| `web/log-panel.html` | 页签条第 5 项 + `#panelPreview`（输入区 / 预览区 / 参数 / 三个内部页签 / 底部执行行）；原工作台脚本并入同一 IIFE，op 加 `preview-` 前缀。 |

协议要点：

- 页面 → 宿主：`preview-ready` / `preview-render` / `preview-format` / `preview-load-file` /
  `preview-clear` / `preview-copy` / `preview-export`（`dialect` 仍被受理但只回一句只读提示）。
- 宿主 → 页面：仍是**一条** `sqlv-logs` 的 `state`，新增 `tabs.preview` 与 `selectTab`。
  `tabs.preview.replaceInput` 是一次性的（只有重写输入框的 op 才置位，下一次推送自动回落），
  避免日志面板的其它推送（过滤、采集刷新）覆盖用户正在输入的文本。
  `selectTab` 会一直随 state 下发，直到页面回 `{op:"tab"}`——页面在应用 `selectTab` 后正好会发这条，
  所以页面加载晚于命令推送时也不会漏掉切换。

## 3a 跨视图消息协议（L42 定稿）

L42 把预览从「日志面板页里的一段 DOM」抽成**一份模块、两个挂载点**：`web/preview.js`
（`mountPreview(root, deps)`）由 `web/log-panel.html` 挂到第 5 页签，`web/preview.html`
是同一模块的独立整页，留给 API 1.18 的 `[[contributes.dialogs]]`。样式单独成
`web/preview.css`，两个页面都用 `<link>` 引同一份（面板页不再内联预览样式）。

因此协议分两层：**op 层**（页面 → 宿主，下面 §3a.1 全表）与**承载层**
（宿主 → 预览，§3a.2 说明「推到哪」由谁决定）。op 名在页面上带 `preview-` 前缀，
宿主 `handle_preview_message` 先剥前缀再匹配（`preview-render` → `render`）；
这样日志面板自己的 `clear` / `copy` / `export` 与工作台的不会撞车。

### 3a.1 op 全表（页面 → 宿主）

「出参」一栏指宿主随后下发的 `tabs.preview` 里受影响的部分；所有 op 都由
`log_panel::handle_panel_event` 在同一次事件末尾补发一条完整 `state`（唯一例外是
`preview-ready` 之后的首次推送，见 §3a.2）。错误码列为 `CliError::KEY_*` 常量或空
（空 = 不失败，只可能改写 status 文案）。

| # | op | 入参 | 出参（`tabs.preview` 内） | 错误码 | 触发点 | Rust 分支 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | `preview-ready` | — | `model` / `status`（按已有模型决定是否 `replaceInput`） | — | 页面脚本就绪、独立页 `preview.html` 启动时 | `"ready"` |
| 2 | `preview-render` | `text`（必填，可为空串）、`kind`（`sql`/`xml`/空=自检） | `model.*`、`replaceInput=true` | — | 输入区「解析」按钮、`Ctrl+Enter` | `"render"` |
| 3 | `preview-format` | `text`（SQL 原文） | `model.sql` 格式化后重渲染、`replaceInput=true` | — | 输入区「格式化」、预览区「格式化 SQL」 | `"format"` |
| 4 | `preview-refresh` | `text`（空则回落 `model.raw`）、`kind` | 同 render；空输入不清空预览 | — | 预览区「刷新」 | `"refresh"` |
| 5 | `preview-load-file` | — | 选中文件后渲染，`replaceInput=true`、`status` | —（宿主 `host::pick` 失败写 status） | 输入区「从文件加载」 | `"load-file"` |
| 6 | `preview-clear` | — | 模型清空、`replaceInput=true`、`status=已清空` | — | 输入区「清空」 | `"clear"` |
| 7 | `preview-copy` | — | 只改 `status`（复制成功 / 空） | —（`copy_to_clipboard` 出错上抛） | 预览区「复制 SQL」 | `"copy"` |
| 8 | `preview-export` | — | 只改 `status`；正文写 Output 通道 | —（`common::emit` 出错上抛） | 「更多」→「导出」 | `"export"` |
| 9 | `preview-params` | `values: string[]`（按位置） | `model.sql` 回填、`model.params=values`、`status` | — | 参数列「重绑定」 | `"params"` |
| 10 | `preview-rollback` | — | 只改 `status=无法生成回滚`（入口本身禁用） | — | 「更多」→「回滚」（禁用的兜底分支） | `"rollback"` |
| 11 | `preview-dialect` | `value`（被忽略） | 只改 `status=方言只读` | — | 旧页面兼容，本版页面不发 | `"dialect"` |
| 12 | `preview-send` | `line: number`（可缺省）、`selectTab: bool`（默认 true） | 跨视图投递：取日志行渲染进 `model`、`replaceInput=true`；缺 `line` 只请求切页签 | — | 日志工具栏「快速预览」（L42 改走此 op） | `"send"` |

页面侧还有两个**不属于预览模块**的 op 参与同一状态机，列在这里以免混淆：
`{op:"tab", tab}` 由页签条上报当前页签，宿主据此 `note_page_tab()` 清掉待切请求，
并在此处执行 `render.formatOnPreview`（L34）；`{op:"open-line", line}` 是行双击/右键
「预览」的老路径，仍由 `log_panel` 直接调 `commands::open_workbench::run`。

### 3a.2 承载层：推到哪个视图

宿主的推送目标由 `views::workbench::preview_target()` **一处**决定，不在调用点写死：

| 目标 | 今天的值 | `PreviewTarget::view_id()` | 投递方式 |
| --- | --- | --- | --- |
| 页签（`Tab`） | 固定 | `sqlv-logs` | `tabs.preview` 随该页 `state` 下发；`send_to_preview` 自身不再额外推送（否则一次 op 两遍） |
| 弹窗（API 1.18 后） | 未实现 | `sqlv-preview`（拟） | `{op:"preview-tab", tab}` 单独投递；`web/preview.html` 已按此形状解析 `message.tab` |

`selectTab` 与 `replaceInput` 都是一次性：前者由页面回 `{op:"tab"}` 消费，后者由
`preview_tab()` 取走。`preview.html` 与面板页对 `state` 的解析完全相同
（`tabs.preview` → `applyTab`），所以换承载方式不改页面。

### 3a.3 面板页与预览页的边界

- 面板页：只保留「日志列表 / 三个输入页签 / 页签条」，预览部分只留一个空容器
  `<div class="panel" id="panelPreview" hidden>`；`mountPreview` 往里注入 DOM。
- 预览模块：自己持有 `model/labels/dialect/tab/mode` 与全部事件；`post` 由调用方注入，
  面板页传自己的（共用一份 `openidea` 句柄），独立页用默认实现。
- 两个页面都不碰 `localStorage` / `fetch` / `innerHTML`：包页是不透明源，且模块用
  `DOMParser` 解析自带模板后逐节点导入。

## 4 与原版的差异（对用户可见）

1. **第 5 页签常驻，没有关闭按钮。** 原版该页签由 Registry 键
   `sqlvis.preview.standaloneTab`（默认 true）决定是否挂载，`addTab` 不带 removable，页签上没有 ×；
   键关闭时 `open-workbench` 只弹一条轻通知指路开关，不静默。本版暂不引入该开关，页签始终挂在
   页签条上，也不做 × 关闭（原因：加键会动 `settings.schema.json` 的 42 项计数，由主控另开一趟统一处理；
   加关闭按钮则会与「常驻」语义自相矛盾）。
2. **没有「独立预览窗口」入口。** 原版工作台另有一个独立 tool window 形态；本版只有页签形态。
3. 「执行 SQL」仍禁用（插件不执行用户 SQL），提示文案不变。
4. 工作台不再有宿主工具栏按钮（`copy` / `export`）：包页本身不画宿主工具栏，
   按钮都在页内，与 L22 的另外三个页签同口径。
