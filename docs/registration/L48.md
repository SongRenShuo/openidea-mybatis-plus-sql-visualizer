## 3. 设置项

| 键 | 页面 / 分组 | 类型 | 默认 | 标题 | 消费者 |
| --- | --- | --- | --- | --- | --- |
| `preview.presentation` | SQL Preview / Preview | enum `dialog` \| `tab` | `dialog` | `Open preview in` | `src/views/workbench.rs::preview_target()`，每次打开预览时读，`needs_restart: false` |

读不到的语义：键未设置、值是错误类型、值不在枚举里（例如 `side-panel`）一律按 `dialog`——
弹窗是默认外壳，页签只有用户显式选 `tab` 才生效。单测
`the_preview_target_follows_the_presentation_setting` 钉住这四种输入。

## 4. 新 op

| op | 入参 | 行为 | Rust 分支 |
| --- | --- | --- | --- |
| `preview-open-dialog` | 无 | 页签挂载点的「在弹框中打开」：在该消息的事件上下文里 `views::reveal("sqlv-preview")`；对话框里该按钮隐藏，不会发这个 op | `"open-dialog"` |

对话框自己发的仍是既有 `preview-*` op 全集（`preview-render` / `preview-format` / `preview-copy` /
`preview-diff` / `preview-send` …），宿主对每条都回一次 `{op:"preview-tab", tab}`；页签的推送通道
（面板 `state`）不变。

## 5. `closed` 的语义

关掉弹窗时 `src/views/log_panel.rs` 的 `Views::handle` 把 `ViewEvent`（宿主以 `Other { kind: "closed" }`
送达，SDK 的 `ViewEvent::closed()` 是判据）交给 `workbench::handle_dialog_event`，后者调
`dialog_closed()`：

- **清掉**：`select_pending`（「下一次推送请打开预览页签」的开标记）、`replace_input`（一次性改写输入框）、
  `handoff`（一次性 `render.formatOnPreview` 标记）。三者都只描述一次已经无处可投的推送。
- **保留**：`model`（SQL、参数、置信度、来源、原因、建议）、`mapper_xml`（语句切换器要用的文档）、
  `status`（最后一行状态）、`display`（关键字换行 / 竖向排列）。

所以关掉再开，页面 `preview-ready` 握手拿回来的还是上次的输入与结果——与原版
`SqlPreviewDialog` 关掉再开保留内容一致。断言：`the_dialog_closes_without_losing_the_last_render`
（workbench）与 `the_preview_dialog_is_routed_to_the_workbench`（log_panel，经 `Views` 路由端到端）。

## 6. 遗留与风险

1. **真机未走查**：本车道没跑 runIde。「弹窗真的弹出、Esc 真的关闭、尺寸真的被记住」只有 IDE 里看得到；
   代码侧能钉的是清单声明、`views::reveal` 的调用上下文、`closed` 路由、页面门控。
2. **设置标题未本地化**：`locales/*.json` 不在本车道可改范围，`Open preview in` 在中文界面显示英文原文。
   主控补两条 catalog 即可（`"Open preview in": { en, zh: "预览打开方式" }` 之类）。
3. **`src/settings.rs` 越界**：见 §2 的说明，属「schema 与代码定义必须双向一致」的构造性要求。
4. **原版对话框有、平台没有的项**：
   - 原版 `SqlPreviewDialog` 的窗口位置/显示器记忆：平台只记住尺寸（`rememberedDialogSize`），位置由宿主决定。
   - 原版对话框有自己的标题栏动作（工具栏按钮）；平台对话框的标题栏由宿主画（标题 + 关闭），
     插件只能把动作放进页面里——本版所有动作本来就在页面工具栏，无缺口。
   - 原版 `DialogWrapper` 的「OK/Cancel」语义：预览窗没有提交动作，关闭即取消，无需映射。
   - 模态性带来的「编辑器不可点」：平台 `Dialog` 由宿主保证，插件侧不再单独处理。
5. **页签与弹窗同时存在**：设置只决定预览「送到哪」，工具窗第 5 页签仍可打开并操作；两边共享同一个模型
   与一次性标记。`replace_input` 是一次性的，弹窗作为目标时由它消费，页签那边要等下一次渲染才会重写输入框
   （模型本身始终一致）。这是刻意取舍：不为双挂载点复制推送通道。
6. **`docs/registration/SUMMARY.md` 的清单计数陈旧**（views/commands/mcpTools 仍是首版读数），
   属主控重生成范围；本车道只在本文件记录 dialogs 这一条。
