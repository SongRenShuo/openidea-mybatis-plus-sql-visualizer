# L12 注册申请（命令接线与捕获命令 T4-2/T4-4）

本车道把捕获链（L7）、日志面板（L5）、日志解析（L4）接到命令层：7 条命令、一条
`websocket-ready` 事件接线、一个可选 Java agent 声明。以下片段由主控在「注册汇总」时落到
`plugin.toml` / `src/lib.rs` / `settings.schema.json` / `locales/*.json`。本车道不改这些文件。

## plugin.toml — 命令

```toml
[[contributes.commands]]
id = "capture-start"
title = "MyBatis SQL: Start Capture"
category = "MyBatis SQL Visualizer"

[[contributes.commands]]
id = "capture-stop"
title = "MyBatis SQL: Stop Capture"
category = "MyBatis SQL Visualizer"

[[contributes.commands]]
id = "capture-status"
title = "MyBatis SQL: Capture Status"
category = "MyBatis SQL Visualizer"

[[contributes.commands]]
id = "capture-poll"
title = "MyBatis SQL: Poll Capture"
category = "MyBatis SQL Visualizer"

[[contributes.commands]]
id = "capture-open-log"
title = "MyBatis SQL: Open Capture Log"
category = "MyBatis SQL Visualizer"

[[contributes.commands]]
id = "open-logs"
title = "MyBatis SQL: Open SQL Logs"
category = "MyBatis SQL Visualizer"

[[contributes.commands]]
id = "open-workbench"
title = "MyBatis SQL: Open Workbench"
category = "MyBatis SQL Visualizer"
```

- `capture-start [port]`：端口优先序＝参数 → `capture.port` 设置 → `17890`。连
  `ws://127.0.0.1:<port>/mpsv`，订阅 `websocket-ready`（进程内一次），下发首帧
  `CONFIG {"disabled":false}`（agent watchdog 收不到 CONFIG 会停止上报）。输出里固定带一行
  「agent 需配置 `port=`」的指引：**端口发现是已知缺口**，agent 在 `port <= 0` 时直接放弃，
  插件不做也不假装自动发现。
- `capture-stop`：下发 `CONFIG {"disabled":true}`、关闭 socket、输出累计帧数/坏帧/丢弃数。
  未连接是**可读的空操作**（不报错）。
- `capture-status`：只读快照（端口/URL/socket/帧数/坏帧/丢弃/排队/最近错误）。未连接时给出
  `capture-open-log` 的替代提示。
- `capture-poll`：手动 drain 一次（≤256 帧），打印本批与累计统计。事件路径调用同一个
  `bridge::poll`（不写 Output，避免每个事件刷屏）。
- `capture-open-log <path>`：`Project::read_file` → `core::log::parse` 统计 →
  `views::log_panel::set_log_text` → `reveal_view("sqlv-logs")`。条目数超过 `logs.pageSize`
  时输出一行提示，给出条目数与 `logs.pageSize` 当前值（面板实际按 viewport 分页，
  `logs.pageSize` 是本项目统一的日志页大小，`render-log` 用它作为首屏上限）。
- `open-logs`：`reveal_view` + `refresh_view("sqlv-logs")`。
- `open-workbench [sql|@path]`：构造 `{op:"load", model:{sql, params:[], dialect, confidence,
  source?}, labels:{…}}` 经 `post_view_message("sqlv-workbench")` 下发，再 `reveal_view`；
  同时写 `views::workbench::set_model`，否则页面加载完成后的 `{op:"ready"}` 握手会用空模型
  覆盖这次 load。

## plugin.toml — 能力

```toml
[capabilities]
required = ["project.read", "events"]
# 连接本机 agent 的 loopback WebSocket（平台无裸 socket）。
optional = ["net:127.0.0.1", "clipboard"]
```

- `events`（Low）：接收 `websocket-ready` 唤醒消费端；缺省时只剩 `capture-open-log` 手动路径。
- `net:127.0.0.1`（Medium，optional）：**为什么需要**——插件作为客户端连 agent 在本机
  loopback 监听的捕获 WebSocket；拒绝时 live 捕获不可用，日志文件路径照常可用。
- 保持 `clipboard`（L5 已声明）不变。

## plugin.toml — 激活与 Java agent

```toml
activation = ["on-command:*", "on-event:websocket-ready"]

[[contributes.javaAgents]]
path = "agent/mps-sql-agent.jar"
args = "port=17890,stackFrames=24"
vmOptions = ["-Dmpsv.capture.transport=ws"]
```

- `args` 的键以主仓 `AgentArgs.parse` 为准：`port` / `logLevel` / `disable` / `stackFrames`
  （`;` 或 `,` 分隔均容忍；未知键静默忽略）。`port` 必须与 `capture.port` 或用户传入的
  `capture-start` 端口一致，否则两边各说各话；`port=0` 时 agent 放弃上报。
- 传输开关是 JVM 系统属性（`CaptureTransportMode.TRANSPORT_PROP`），只认 `vmOptions`，
  **不要**写进 `args`。
- 声明 `[[contributes.javaAgents]]` 会派生 high-risk 能力 `java.agent`，不要重复列。
- `path` 是包内文件；jar 未进包前 `openidea-plugin check` 会拒绝整个 manifest（L7 待决前提 2）。

## settings.schema.json

```json
"capture.port": {
  "type": "number",
  "title": "Java agent capture WebSocket port",
  "default": 17890,
  "minimum": 1,
  "maximum": 65535
}
```

放在 Log 组即可。读取走 `src/settings.rs` 的封装（`settings::get_i64` / `host::setting_number`）；
非法值（0、负数、>65535）由命令报 `capture.port.invalid`，不静默回退。

## src/lib.rs

`run_command` 增加 7 个分支（`render_xml` 的接线由主控按 L11 的方式一并合并）：

```rust
commands::capture_start::ID => commands::capture_start::run(ctx, arg),
commands::capture_stop::ID => commands::capture_stop::run(ctx, arg),
commands::capture_status::ID => commands::capture_status::run(ctx, arg),
commands::capture_poll::ID => commands::capture_poll::run(ctx, arg),
commands::capture_open_log::ID => commands::capture_open_log::run(ctx, arg),
commands::open_logs::ID => commands::open_logs::run(ctx, arg),
commands::open_workbench::ID => commands::open_workbench::run(ctx, arg),
```

`Main::handle_events`（新增实现，当前用的是 trait 默认空实现）：

```rust
fn handle_events(&mut self, events: &[openidea_plugin::Event], ctx: &Invocation) {
    for event in events {
        if matches!(event, openidea_plugin::Event::WebSocketReady(_)) {
            // 不 panic、不阻塞：内部最多 drain 256 帧，失败只记 WARN。
            let _ = crate::capture::bridge::on_websocket_ready(ctx);
        }
    }
}
```

- `bridge::on_websocket_ready` 对「没有会话」和 host 失败都返回 `Ok(())` 并写 WARN 日志，
  所以事件路径不会把错误抛进 `handle_events`。
- 面板刷新走 `RefreshState`（`log.refreshIntervalMs`，默认 250 ms），`poll` 只在
  `RefreshAction::Refresh` 时调用 `refresh_view("sqlv-logs")`。

## 待决前提（主控裁决）

1. **端口发现**：manifest 的 agent `args` 是静态字符串，agent 不会把实际端口告诉插件。
   本车道按「设置固定端口 + 命令显式覆盖」落地，并在输出里明示 agent 需要 `port=`；
   真机验证前需要用户把 `capture.port` 与 agent 的 `port` 对齐（或由主控采纳 L7 的
   `.mpsv/agent-<pid>.port` 方案，届时 `capture-start` 可优先读该文件）。
2. **agent jar 进包**：与 L7 待决前提 2 相同，`agent/mps-sql-agent.jar` 不存在时 `check` 拒绝。
3. **真机未验**：本车道的连接全部在 MockHost 上验证（mock 仅接受 `wss://`，生产走 loopback
   `ws://`）；真机 `ws://127.0.0.1` 握手与 `websocket-ready` 唤醒需在 runIde/真 IDE 中验收。
