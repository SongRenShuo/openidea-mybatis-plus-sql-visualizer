# L28 注册片段：日志来源接上面板 + 跳转 / 聚焦 / 右键

本车道把 L25 产出的「来源」（`core::log::{SourceRef, LineSource, LogSources}`）接进
`sqlv-logs` 面板，并补齐原版的三类交互：跳转到 Java / Mapper XML、按方法或请求聚焦、
行右键的删除与屏蔽。

`plugin.toml` 由主控独占，本车道**未改**，也**不需要**改。

## plugin.toml

无变化：没有新命令、视图、provider、documentIndexer、MCP 工具。

### 为什么不需要新能力

「跳转 Java / 跳转 Mapper XML」用的是 SDK 的 `host::open_location(path, line, column)`
（API 1.15 `views.open-location`）。WIT 注释写明它只要求「从某个窗口的 command/event 调用」，
打开**项目内**文件仍走 `project.read`——本插件 `required = ["project.read", "events"]`
已声明，所以两个跳转项直接可用：

- 不需要 `editor.read` / `editor.write`（那是 `editor.open-editors`、`editor.document-at`
  的要求，本车道没用）；
- 不需要 `fs.read`（路径由 `project.read_file` 之外的宿主索引给出，见下）。

若宿主拒绝打开（无窗口上下文、项目已关闭），面板**降级**：把 `文件:行` 复制到剪贴板并在
Output 通道打印一行说明（`view.logs.jump.unavailable`），不会静默失败。

## 索引方案（大工程怎么扛）

面板的跳转目标来自两个**进程级内存索引**，都在 `src/indexer/`，都**不读文件**：

| 索引 | 键 | 值 | 用途 |
| --- | --- | --- | --- |
| `JavaMethodIndex`（L25 已有） | `class#method` | 文件 + 0 基行 | 跳转 Java |
| `XmlStatementIndex`（本车道新增） | `(namespace, id)` | 文件 + 0 基行 | 跳转 Mapper XML |

### 谁喂、什么时候喂

`impl DocumentIndexer for crate::Main::index`（`[[contributes.documentIndexers]]`
extensions `xml`/`java`）在**项目打开时批量、之后每次文件变化**由宿主在可取消的后台批次里调用。
本车道在那一个回调里加一行 `index_source(&doc.path, &doc.text)`，两种文档按扩展名分流。

- 因此**没有**新命令、没有自建工作区扫描、没有前台 EDT 扫描：宿主已经是唯一的批量入口，
  且它的批次本来就是后台 + 可取消。
- 面板推送路径只做内存查询：`HashMap` 一次 + 同名方法/语句数个比较，**不读文件、不建索引**。

### 预算与计数

- `JavaMethodIndex` 沿用 L25 的 `JavaIndexBudget::default()`（4096 文件 / 单文件 2 MiB /
  合计 16 MiB）；超限的文档被拒并计入 `skipped_files`，`target`/`build`/`out`/`.worktrees`
  等目录整段排除。
- `XmlStatementIndex` 自带 4096 文件上限，同样计数。
- 同一路径重入是**替换**（`add_file` 先 `remove_file`），保存不会把条目翻倍；两处都有单测钉住。
- `indexer::index_stats()` 暴露 `{java_files, java_methods, java_skipped, xml_files,
  xml_statements, xml_skipped}`，面板/诊断可直接读。

### 为什么另起一个 XML 索引

`JavaMethodIndex::resolve_statement(namespace, id)` 的语义是「statement id → **mapper 接口方法**」，
那是「跳转 Java」的目标；把它当「跳转 Mapper XML」用会跳到错的文件。`MapperGraph::resolve`
能给出 XML 位置，但每次查询都重建全部文档的 edges（O(文档数)），放不进逐行推送路径。
所以新增的是最小索引：每条语句只存 `file / namespace / id / line`，查询是 `id` 哈希 + 命名空间
段比较；命名空间匹配复用 Java 侧同一条规则（`dotted_suffix_matches`，支持 Spring 的
`c.e.m.mapper` 缩写），两侧口径一致。

## 未实现 / 已知边界

- **多候选不猜**：一个方法有重载、或两个同名类都声明它 → `lookup_source_unique` 返回 `None`，
  该行不显示 `[文件:行]`、右键「跳转 Java」置灰；语句在两个匹配的 namespace 里都存在时
  「跳转 Mapper XML」同理。页面不发请求，宿主也不猜。
- 预算外的文件（>4096 个 Java / XML）不参与解析，跳转项对该行置灰。
- 聚焦一次只保留一个 chip（方法**或**请求）；原版的多 chip 并集是后续细化。
- 屏蔽是**会话级**内存集合（`clear` 或 `恢复被屏蔽的方法` 清除），不写设置、不持久化。
