# L7 注册申请（捕获链 T4-1~T4-5）

> 本文件由车道 L7 写，主控在 `chore: 注册汇总` 时统一应用。**不要**直接改 `plugin.toml`。

## plugin.toml

### Java agent（T4-2）

```toml
[[contributes.javaAgents]]
path = "agent/mps-sql-agent.jar"
args = "stackFrames=24"
# ws 传输是 JVM 系统属性（EventBus.start 启动时读一次），不是 agent args；
# 必须经 vmOptions 注入，否则 agent 仍走裸 TCP，平台侧连不上。
vmOptions = ["-Dmpsv.capture.transport=ws"]
```

- `vmOptions` 需要 `engines.openidea = "^1.14"`（本仓 ^1.15 满足）；每个 flag 单行、以 `-` 开头、
  不含空格。`-Dmpsv.capture.transport=ws` 同时满足这三条。
- `args` 里的 `transport=ws` 会被 `AgentArgs` 当未知键静默忽略（未知键容忍是既有契约），
  **不要**写在那里；传输开关只认 `CaptureTransportMode.TRANSPORT_PROP`。

- `path` 必须是包内文件（manifest 校验不允许 `..`、绝对路径、指向包外的软链）。jar 由主仓
  `sub-projects/sql-visualizer-agent` 产出（`agentFatJar` → `build/dist/mps-sql-agent.jar`），
  发版构建时需复制进本包；**当前仓库尚无该文件**，在复制前 `openidea-plugin check` 会因
  `path` 不存在拒绝整个 manifest。这是应用本片段的前置条件（见文末「待决前提」）。
- 声明 `[[contributes.javaAgents]]` 会自动派生 high-risk 能力 `java.agent`，**不要**在
  `[capabilities]` 里再列它（列了 manifest 直接被拒）。

### 激活（T4-2）

```toml
activation = ["on-command:*", "on-event:websocket-ready"]
```

`websocket-ready`（API 1.6，SDK `EventKind::WebsocketReady`，名字 `websocket-ready`）表示
host 侧 WebSocket 有帧可 drain 或收到最终 close；捕获消费端靠它被唤醒，而不是轮询。

### 命令

```toml
[[contributes.commands]]
id = "capture-start"
title = "MyBatis SQL: Start Capture"
category = "MyBatis SQL Visualizer"

[[contributes.commands]]
id = "capture-stop"
title = "MyBatis SQL: Stop Capture"
category = "MyBatis SQL Visualizer"

[[contributes.commands]]
id = "capture-open-log"
title = "MyBatis SQL: Open Capture Log"
category = "MyBatis SQL Visualizer"
```

- `capture-start`：启动/连接 agent 的 loopback WebSocket，订阅 `websocket-ready`，下发首帧
  CONFIG（`{"disabled":false}`）。没有 `process:java` 或 `java.agent` 未授权时，直接落到
  `capture-open-log` 的手动路径并明示原因。
- `capture-stop`：下发 `{"disabled":true}` 后关闭连接（agent 侧同时清空已排队事件，语义与
  IntelliJ 版一致）。
- `capture-open-log`：无 agent 时的替代路径——选一个导出的运行日志文件，用
  `Project::read_file`（项目内）或 `host::fs::read_file`（项目外，需要 `fs.read:<path>`）做
  增量尾随，解析器由 L4 注入（`src/capture/file_tail.rs::LineSink`）。

## capabilities

```toml
[capabilities]
required = ["project.read", "events"]
optional = ["process:java", "net:127.0.0.1"]
```

- `events`（low）：接收 `websocket-ready`、在激活后持续唤醒消费端；缺省时 live 捕获不可用。
- `process:java`（high，optional）：**为什么需要**——启动/注入 agent 到目标 JVM 内，捕获真实
  SQL 执行事件。拒绝时插件仍可用：只剩 `capture-open-log` 的日志文件路径，UI 明示「未附加 agent」。
- `net:127.0.0.1`（medium，optional）：**为什么需要**——插件作为客户端连到 agent 在同一机器
  loopback 上监听的 WebSocket（平台沙箱无裸 socket，`WebSocket::connect` 需端点所在 host 的
  `net:<host>` 授权）。URL 由 `src/capture/ws.rs` 校验：`ws://` 只允许 127.0.0.1/localhost，
  非 loopback 必须 `wss://`，且拒绝凭据/query/fragment。

## README 能力表

| 能力 | 风险 | 为什么需要 |
| --- | --- | --- |
| `process:java` | High（optional） | 启动 Java agent 在目标进程内捕获 SQL 执行事件；拒绝后降级为日志文件尾随。 |
| `net:127.0.0.1` | Medium（optional） | 连接 agent 在本机 loopback 监听的捕获 WebSocket（平台无裸 socket）。 |
| `events` | Low | 接收 `websocket-ready` 唤醒捕获消费端。 |

## 待决前提（应用前必须解决，主控裁决）

1. **静态 `args` 装不下运行期端口**（实测 SDK/README）：manifest 的 `[[contributes.javaAgents]]`
   `args` 是一行固定字符串，而 IntelliJ 版是每次 Run 前置协商临时端口后动态注入。当前 agent
   `AgentArgs.port <= 0` 即放弃上报。可行方案（推荐 a）：
   - a) agent 支持 `port=0`：绑定临时端口后把实际端口写到项目内
     `.mpsv/agent-<pid>.port`（agent 直接写文件，不经插件），插件 `project.read` 读取后
     `WebSocket::connect`；
   - b) 设置页固定端口 + 冲突检测与回退。

   在选定前，`capture-start` 无法真正连上 agent，只有 `capture-open-log` 路径可用。
2. **agent jar 进包**：`path = "agent/mps-sql-agent.jar"` 需要构建时把主仓产物复制进来；当前
   仓内没有该文件，`check` 会直接拒绝 manifest。谁来做这一步（L10 发行构建 or CI 新增步骤）
   需主控定。
3. **`javaAgents` 覆盖范围**：OpenIDEA 只在 Application / Spring Boot / JAR Application 配置
   注入，测试（JUnit）、Maven/Gradle goal、应用服务器、远程目标不注入——与
   `docs/LIMITS.md` 的捕获边界需一致（不在本车道的改动范围）。
4. **`fs.read:<path>`**：`capture-open-log` 读项目外日志需要该授权；manifest 不能按运行期路径
   声明。建议 MVP 只支持项目内日志（`project.read` 足够），项目外路径由用户在设置里显式加
   grant（UI 指引属 L5）。
