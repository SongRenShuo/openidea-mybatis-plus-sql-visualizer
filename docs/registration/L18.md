# L18 注册申请（SQL 工作台：布局复刻与协议扩展）

本车道把 `sqlv-workbench` 页面（`web/workbench.html`）按 IntelliJ 原版「SQL 预览」工作台
（`SqlStandalonePreviewPanel` + `SqlPreviewPanel`）重做，并把宿主协议从单一的 `{op:"load"}`
扩展成一次 `state` 推送 + 六个操作 op。

**不需要改 `plugin.toml`**：视图 id、`web` 路径、命令、能力都没变，本车道也不新增命令 / MCP 工具 /
provider。下面只有「文案键」一类需要主控确认，另有两处平台缺口与一处设置键不一致需要主控决策。

## 1 文案键

派活要求把新文案「追加」到 `locales/en.json` 与 `locales/zh-CN.json`，本车道已按要求只追加、未重排。
但要注意本仓的实际查表在 `src/i18n.rs` 的 `TABLE`（`t()` 只读它），`locales/*.json` 是 IDE 目录翻译
（English 源串 → 译文，用于设置页标题、命令名这类清单字符串）。所以这批键**两处都写了**：

- `src/i18n.rs`：权威，键名 `view.workbench.*`；
- `locales/*.json`：按派活要求追加的点号键（IDE 只按源串查表，这些点号键不会被查到，纯登记）。

若主控决定只保留一处，**保留 `src/i18n.rs`**，删掉 locales 里的 `view.workbench.*` 点号键即可，
行为不变。反过来只留 locales 会让页面全部显示键名。

新增键（`view.workbench.` 前缀）：

| 键 | 用途 |

## 2 协议 op（页面 → 宿主）

| op | 入参 | 行为 |
| --- | --- | --- |
| `ready` | — | 页面脚本就绪，宿主回一次 `state`（与 `open-workbench` 的 `load` 握手并存） |
| `render` | `text`、可选 `kind`（`sql`/`xml`，缺省按内容识别） | 纯 SQL 原样采用（`exact`）；含 `<mapper>`/语句标签时走 `core::xml::MapperSet` 渲染第一个语句；unresolved 不产出 SQL，只回原因 |
| `format` | `text` | SQL 走 `core::format::format`（当前方言）后重渲染；XML 片段不格式化并说明 |
| `load-file` | — | 列工程内 `**/*.xml` + `**/*.sql`（各 200 条上限）→ `host::pick` → `Project::read_file` → 按扩展名选 `sql`/`xml` 渲染 |
| `clear` | — | 清空模型并回 `state`（页面同时清输入框） |
| `copy` / `export` | — | 复制可执行 SQL 到剪贴板 / 写 `Output` 通道（`-- mybatis-sql workbench export` 头 + 格式化 SQL） |
| `dialect` | `value` | **只读**：只回一条说明状态，不改模型（旧页面若仍发此 op 不会卡住） |

宿主 → 页面：`{op:"state", replaceInput, model:{sql, params, dialect, confidence, source, kind, reason,
advice, tabs:{sql, formatted, raw, columns}}, dialect:{name, isDefault, capabilities}, labels:{…},
status:{text}}`。`replaceInput` 为真时才覆盖输入框内容（render / format / load-file / clear），
否则保留用户正在编辑的文本（copy / export / ready 等）。旧页面要的 `{op:"load"}` 仍然发
（`push_model()`，`commands::open_workbench` 与 `capture::bridge` 的载荷没动）。

## 3 降级与取舍（都要在发版说明里对用户可见）

| 项 | 本版做法 | 原因 |
| --- | --- | --- |
| 方言 | 只读标签，取自设置 `dialect.default`（回落旧键 `sql.dialect`，最后 `MySQL（默认）`），旁注「在 Settings → MyBatis SQL Visualizer 修改」，不给链接 | 原版面板也没有方言下拉，方言来自设置；派活明确要求不做可点链接 |
| 执行 SQL | 按钮保留但 `disabled`，tooltip 写明「本插件不执行用户 SQL；EXPLAIN 走引擎侧」 | 平台 `database` 不执行 SQL，插件本身也不执行 |
| 在弹框中打开 | 按钮保留但 `disabled`，tooltip 说明「工具窗就是工作台」 | 本版没有独立弹框形态；开一个不存在的弹框是假按钮 |
| 从文件加载 | 工程内 `.xml`/`.sql` 列表 → `host::pick`（不是系统文件选择框） | SDK 1.15 没有文件选择 API（只有 `pick` / `pick_directory`）；`host::open_editors` 与 `ctx.editor().document()` 都要 `editor.read` 能力，而本插件未声明、`plugin.toml` 由主控独占 |
| 参数区 | 只读展示渲染出的参数值，不支持填值后重新绑定 | 原版参数表可编辑并重绑定；本车厢范围只到布局复刻，重绑定需要 MCP/引擎侧的参数入口 |
| 列信息页签 | 始终存在；无列数据时显示「本版不连接数据库，未获取列信息」 | `RenderOutput` 不带列元数据，凭空推导列名属于猜测 |
| 显示模式 | 普通 / 格式化 两档（格式化取宿主的 `tabs.formatted`，宿主侧用当前方言格式化） | `core::format` 只有一种格式化形态，原版的竖排 / 关键字换行没有对应实现，不做假模式 |
| 性能建议行 | 只给「N 条（严重 x，警告 y）」计数 | `core::perf` 的 `message_key`（`perf.*`）在本仓没有译文，直接显示会漏裸键；明细走 `perf-advice` 命令 |

## 4 需要主控决策的两处

### 4.1 设置键不一致

`settings.schema.json` 与 `src/settings.rs` 声明的是 `dialect.default`；`commands::common::DIALECT_SETTING`
读的是 `sql.dialect`。设置页写的是前者，`configured_dialect()` 读的是后者 → 用户在设置页改了方言，
命令侧读不到，一直回落 MySQL。

本车道读法：先 `dialect.default`，再 `sql.dialect`，都空则 `MySQL`（并标「默认」）。建议主控把
`commands::common::DIALECT_SETTING` 统一成 `dialect.default`，之后工作台可以只读一个键。

### 4.2 `ctx` 没传到视图 handler

平台文档写明：工具窗视图的 `Views::handle(view, event, ctx)` 里 `ctx.editor()` 就是该窗口的当前编辑器，
所以「从当前编辑器取选中内容」本来是可行路径之一。但 `src/views/log_panel.rs` 的 `Views for Main`
把 `ctx` 丢成了 `_ctx` 并只调 `handle_workbench_event(event)`。该文件属于日志面板车道，本车道没有动。

若主控以后愿意在 `log_panel.rs` 的 `handle` 里多传一个 `ctx`（一行），工作台可以再加一条「从当前编辑器
加载」的入口；那时还需要在 `plugin.toml` 声明 `editor.read`（低风险能力）。本版不依赖它。
