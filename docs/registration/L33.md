## 1. 形态

### 日志 → SQL

```
Splitter(vertical)
├ 上：日志输入编辑区（普通等宽文本，不做 SQL 高亮）
│   工具栏：转换 / 从剪贴板读取 / 清空
└ 下：SQL 结果编辑区（可编辑）
    工具栏：复制 SQL / 压缩↔多行切换 / 清空结果
底部：状态行（错误红字 / 提示灰字）
```

- 一段日志含多组 `Preparing:`/`Parameters:`（或混有 Hibernate / JdbcTemplate 行）时全部转换，
  组间用 `-- SQL #1`、`-- SQL #2` 注释分隔（仅多组时加组头，单条不加）。
- 每条语句按当前配置方言格式化（`core::format::format`），并补 `;` 结束符。
- 还原后仍含 `?`（参数不足）→ 状态行红字并给出条数；已还原的语句仍照常显示。
- 未识别到任何语句 → 红字给出可粘贴的三种日志格式。
- 结果区可手工改写；「复制 SQL」复制的是**页面上当前文本**（不是宿主草稿）。

### SQL → Java

```
Splitter(vertical)
├ 上：SQL 输入编辑区
│   工具栏：转换 / 格式化 SQL / 清空
│   选项行（独立一行）：生成形态下拉 / 实体类名 / 调用类 / 返回类型
└ 下：Java 结果编辑区（可编辑）
    工具栏：复制代码 / 清空结果
底部：状态行
```

- 生成走既有 `src/mcp/handlers/reverse_sql.rs::run`（入参 `{sql, entity}`，JSON 进 JSON 出），
  本车道没有新写生成器，也没有改 handler 契约。
- 实体为空 → `unresolved`（`gen.java.entity_required`），状态行红字给出原因，不出代码。
- 生成成功 → 状态行灰字「已生成 MyBatis-Plus Java 代码」。

## 3. 宿主 op（页面 → 宿主）

| op | 入参 | 行为 |
| --- | --- | --- |
| `log-to-sql-convert` | `text` | 解析并还原整段日志，写 `tabs.logToSql` |
| `log-to-sql-clear` | — | 清空结果与状态行（输入框由页面自己清） |
| `log-to-sql-read-clipboard` | — | 读剪贴板 → 填入输入框并立即转换；空/无能力各有状态行提示 |
| `sql-to-java-convert` | `text`（`sql` 兼容）、`format`、`entity`、`caller`、`returnType` | 调 `sqlv_reverse_sql`，写 `tabs.sqlToJava` |
| `sql-to-java-format` | `text` | 按配置方言格式化输入 SQL，经 `replaceInput` 回填页面 |
| `sql-to-java-clear` | — | 清空结果与状态行（选项行保留） |
| `copy-text` | `text`、`tab`（`logToSql`/`sqlToJava`） | 复制页面当前文本，并在该页签状态行确认 |

两个清空 op 不区分输入/结果：输入框归页面所有，页面本地清空即可；宿主只负责结果与状态行。

## 4. state（宿主 → 页面，仍在 `{op:"state"}` 里）

```json
"tabs": {
  "logToSql":  {"output": "...", "status": "...", "statusKind": "info|error",
                "input": "...", "replaceInput": false},
  "sqlToJava": {"code": "...", "status": "...", "statusKind": "info|error",
                "options": {"format": "lambda|stringColumns", "entity": "",
                            "caller": "", "returnType": ""},
                "input": "...", "replaceInput": false}
}
```

- `input` + `replaceInput` 是一次性回填通道：只有「从剪贴板读取」和「格式化 SQL」会让宿主
  填页面输入框；`replaceInput` 在每次推送时被取走（`mem::take`），后续推送一律 `false`，
  不会覆盖用户正在输入的内容。
- 旧的 `empty` / `line` / `rawSql` / `params` / `restored` / `confidence` / `ran` / `reason`
  字段全部删除，没有保留两套语义。日志列表选中行不再驱动「日志 → SQL」页签，`log-to-sql`
  op 与 `logToSqlLine` 一并移除。

## 5. 与源码的对应与差异

| 源码 | 本版 |
| --- | --- |
| 上下 Splitter + 每区工具栏 | 一致（可拖动分栏） |
| `-- SQL #N` 组间分隔 | 一致 |
| 参数不足红字 | 一致，并给条数 |
| 压缩↔多行 | 缩短为**纯页面展示切换**：宿主只推多行形态，页面按需折叠空白生成压缩形态；不重转、不请求宿主（源码会重转一次） |
| 单条语句前导注释 `[名称]` | 未做（`SqlStatementNamer` 在引擎 jar 里，本仓未开该口子） |
| 大日志后台转换 | 未做：转换在 view 消息回调里同步完成，几 MB 级粘贴会占用主线程（`docs/LIMITS.md` 未列此项，属本版已知边界） |
| SQL 输入高亮 + 补全 | 只做等宽等宽字体；**补全不做**（平台无 PSI / `textDocument/*` 未开放），也没有引入高亮库 |
| Java 结果高亮 | 不做（同上） |
| 实体推断 / 多候选弹窗 | 不做：无 PSI 无法从项目推断实体。实体类名是**必填输入框**（`sqlv_reverse_sql` 入参就是 `{sql, entity}`，`deny_unknown_fields`） |
| 调用类 / 返回类型影响生成 | 不生效：生成器只接受 `{sql, entity}`。两项仅记录并回显，**非默认值出现时选项行下方常显灰字提示「本版固定生成 Lambda 链…」**，不做点了没反应的下拉 |
| 形态下拉（Lambda / 字符串列名） | 同上：本版固定 Lambda；选「字符串列名」只改变上述提示，代码仍为 Lambda |
| 结果区「执行」 | 未做（本版无执行链入口，见 `docs/LIMITS.md`） |

## 6. 已知限制（对用户可见）

1. **无语法高亮与补全**：两个页签的编辑区都是等宽纯文本；输入区不染色，结果区不染色。
2. **「从剪贴板读取」在真机不可用**：`ui.read-clipboard` 需要 `clipboard.read` 能力，本仓
   `plugin.toml` 目前只声明了 `clipboard`，本车道不得改 `plugin.toml`。宿主区分「无能力」
   与「剪贴板为空」两种提示；要真正可用，需由持有 `plugin.toml` 的车道把 `clipboard.read`
   加入 optional 能力并在 README 能力表说明。
3. **实体必须手填**：留空即 `unresolved`，不猜实体。
4. **形态/调用类/返回类型不参与生成**：见 §5，页面有常显提示。
5. **「发送到」只预填不自动转换**：L32 的 `sendToTab` 把文本放进对应输入框并切到该页签，
   然后由页面回报 `tab` 消费；是否转换由用户点「转换」决定（源码的 `loadFromEntry` 是填入即转，
   本版按车道约定只预填）。
6. **大段日志同步转换**：见 §5。
